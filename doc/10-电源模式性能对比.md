# 平衡、高性能与最佳能效模式性能对比

## 1. 结论

测试日期：2026-10-22

在交流供电、相同 Release 构建和相同测试文件下，**平衡模式整体明显快于最佳能效模式**：

- 普通热打开 P95 快约 `38%`。
- 普通 Tab 切换 P95 快约 `27%`。
- 普通冷启动 P50 快约 `25%`，P95 快约 `5%`。
- 滚动差异较小，平衡模式 P95 快约 `16%`。
- 10 MB 文档热打开 P50 快约 `18%`，切换 P95 快约 `23%`。

两种模式都满足普通冷启动、热打开、Tab 切换和滚动门槛；10 MB Tab 切换在两种模式下仍未达到 50 ms。

补测一轮高性能模式后，高性能与平衡在普通交互上基本持平，没有稳定、成倍的性能收益。

| 项 | 配置 |
|---|---|
| CPU | AMD Ryzen 7 8845HS |
| 电源 | 交流供电，电量约 20% 且正在充电 |
| 基础电源方案 | 平衡，`381b4222-f694-41f0-9685-ff5bb260df2e` |
| 平衡 overlay | `00000000-0000-0000-0000-000000000000` |
| 最佳能效 overlay | `961cc777-2547-4f9d-8174-7d86181b8a7a` |
| 显示 | 1920 x 1080，100% 缩放，96 DPI |
| 构建 | MinGW Release static，wxWidgets 3.3 |
| 采样顺序 | 平衡→节能、节能→平衡、节能→平衡（ABBA + 反向复核） |
| 每轮样本 | 常规冷启动 20、热打开 20、切换 40、滚动 30；10 MB 冷/热各 5、切换 20、滚动 30 |

三轮合计：

- 常规冷启动和热打开各 60 个样本。
- 常规 Tab 切换 120 个样本。
- 常规滚动 90 个样本。
- 10 MB 冷启动和热打开各 15 个样本。
- 10 MB Tab 切换 60 个样本。
- 10 MB 滚动 90 个样本。

## 3. 三轮合并结果

### 普通文档

| 指标 | 平衡 P50 | 平衡 P95 | 最佳能效 P50 | 最佳能效 P95 | 能效模式 P95 变化 |
|---|---:|---:|---:|---:|---:|
| 冷启动 | 332.406 ms | 430.664 ms | 416.981 ms | 453.094 ms | +5.2% |
| 热打开 | 29.581 ms | 37.741 ms | 44.306 ms | 51.917 ms | +37.6% |
| Tab 切换 | 8.088 ms | 10.456 ms | 11.241 ms | 13.273 ms | +26.9% |
| 滚动 | 4.616 ms | 6.167 ms | 5.099 ms | 7.138 ms | +15.7% |

平衡模式滚动最大值为 `7.237 ms`；最佳能效模式出现一次 `20.738 ms` 的单帧，但仍低于 50 ms 验收上限。

### 10 MB 文档

| 指标 | 平衡 P50 | 平衡 P95 | 最佳能效 P50 | 最佳能效 P95 | 能效模式 P95 变化 |
|---|---:|---:|---:|---:|---:|
| 冷启动 | 692.697 ms | 786.315 ms | 818.676 ms | 878.776 ms | +11.8% |
| 热打开 | 367.807 ms | 441.931 ms | 432.578 ms | 454.290 ms | +2.8% |
| Tab 切换 | 58.159 ms | 70.795 ms | 73.964 ms | 86.831 ms | +22.7% |
| 滚动 | 4.881 ms | 6.269 ms | 5.079 ms | 7.274 ms | +16.0% |

10 MB 热打开的 P95 差距被平衡模式少数长尾样本拉近，但 P50 仍有约 18% 差距。

## 4. 冷启动波动说明

平衡模式三轮冷启动 P95 分别为 `659.196 ms`、`345.306 ms`、`430.664 ms`。第一轮前两个样本达到 `862.604 ms` 和 `659.196 ms`，其后均回到约 `331–390 ms`。

最佳能效三轮冷启动 P95 分别为 `476.306 ms`、`426.608 ms`、`451.504 ms`，波动更小但整体中位数更慢。

因此：

- 普通交互性能应参考 P50 和多轮合并结果。
- 冷启动 P95 受 Windows 进程装载、后台扫描和调度影响，但仍需保留长尾数据。
- 当前数据不支持“最佳能效更流畅”的结论。

## 5. 复现

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command `
  "& '.\scripts\compare-power-modes.ps1' -Samples 20 -LargeSamples 5 `
   -Modes @('balanced','efficiency') -OutputName 'ac-check'"
```

原始结果目录：`build\power-performance\ac-abba-a`、`ac-abba-b`、`ac-abba-c`。

脚本会在结束时恢复原电源 overlay。后续 `benchmark.ps1` 生成的 JSON 也会记录电源模式名称、overlay GUID 和供电来源。

本次测试开始前机器在电池供电下使用“最佳能效”。接通交流电后，测试脚本已把交流电模式恢复为“最佳能效”；电池 overlay 在最初的手动切换探测中变为“平衡”，但写回该受保护注册值需要管理员权限。若之后拔掉电源仍希望保持“最佳能效”，请在 Windows 电源设置中重新选择一次。

## 6. 高性能模式补测

高性能模式使用 overlay `ded574b5-45a0-4f42-8737-46345c09c238`，在交流供电下补测一轮：

| 指标 | 高性能 P50 | 高性能 P95 |
|---|---:|---:|
| 普通冷启动 | 311.804 ms | 345.429 ms |
| 普通热打开 | 27.480 ms | 40.056 ms |
| 普通 Tab 切换 | 7.971 ms | 10.454 ms |
| 普通滚动 | 5.164 ms | 6.782 ms |
| 10 MB 冷启动 | 647.135 ms | 654.280 ms |
| 10 MB 热打开 | 344.356 ms | 355.141 ms |
| 10 MB Tab 切换 | 54.416 ms | 59.882 ms |
| 10 MB 滚动 | 4.519 ms | 6.590 ms |

与平衡模式三轮中位数相比：

- 普通冷启动 P50 快约 5%，P95 好于平衡轮次中位数，但仍与平衡模式最好一轮相当。
- 普通热打开和切换差异都在约 2% 内。
- 普通滚动本轮反而慢约 18%，属于测量波动。
- 10 MB 场景本轮更快，但仍不足以抵消最佳能效与平衡之间稳定的交互差距。

结论：在这台 AMD 8845HS 笔记本上，高性能模式相对平衡没有稳定收益，建议日常选平衡。

## 7. 外部计时数据说明

另一台 Intel i5-14500 台式机报告的外部计时结果中，平衡模式 10 MB 冷启动约 `62.79 / 99.78 ms`。该数值不能直接与当前日志口径横比：

- 当前 `cold_start` 从进程创建开始，经过应用初始化、全文 Markdown 解析、首个可见视口布局和绘制后结束。
- 外部轮询窗口句柄或标题时，可能只测到窗口已创建，而此时文档仍可能显示“正在解析”。
- 当前滚动指标从滚轮消息进入处理函数开始，到对应帧完成绘制结束；外部“消息处理时间”可能只测 `SendMessage` 返回耗时，不包含实际绘制。

因此，外部计时和内部日志必须统一终点定义后才能比较。建议外部计时至少同时记录：

1. 窗口首次可见时间。
2. 文档标题首次更新为 Ready 的时间。
3. 首帧可读内容完成时间。

Intel 台式机上“最佳能效”比平衡慢数倍，说明该平台对电源模式更敏感；AMD 笔记本上本轮仅观察到约 5%–38% 的差异。SSD 不是这两组数据差异的主要解释，进程启动、CPU 调频策略和计时终点差异影响更大。

## 8. 是否需要立即做滚动专项优化

当前基准暂不支持立即实施预布局、滚动降级、位图缓存或帧预算切块。

| 模式 | 滚动样本 | `>16.7 ms` | `>50 ms` | 最大单帧 |
|---|---:|---:|---:|---:|
| 平衡 | 90 | 0 | 0 | 7.237 ms |
| 高性能 | 30 | 0 | 0 | 6.875 ms |
| 最佳能效 | 90 | 1 | 0 | 20.738 ms |

结论：

- 平衡和高性能模式下，当前 10 MB 测试文档没有出现超过 16.7 ms 的单帧。
- 最佳能效模式 90 帧中只有 1 帧超过 16.7 ms，且没有超过 50 ms。
- 当前证据不支持引入滚动降级、位图缓存或按帧切块。这些方案会带来内存、闪烁或渐进显示复杂度。
- 预布局是四项中风险最低的候选，但只有在针对实际复杂文档的压力测试中稳定看到“新块进入视口”造成长帧后才值得加入。

当前滚动基准仍有两个边界：

1. 每个滚轮事件间隔约 35 ms，未模拟触控板或高回报率鼠标的连续突发输入。
2. 10 MB 测试文件主要由重复的普通 Markdown 块组成，没有包含单个超大表格、长代码块或复杂 flowchart。

因此最终结论是：**暂不实施生产优化，先补一个连续滚轮 + 复杂块的压力场景**。如果该场景在相同构建上也不能复现 50 ms 以上长帧，则原先的滚动优化方案可以继续搁置。

## 9. 150 KB 连续滚动突发测试

补充测试使用 150 KB Markdown，文件包含中英文段落、列表、引用、代码块和表格。向文档连续投递 120 个滚轮消息，比较平衡与最佳能效模式。

| 模式 | 投递耗时 | 绘制帧数 | P50 | P95 | 最大 | `>16.7 ms` | `>50 ms` |
|---|---:|---:|---:|---:|---:|---:|---:|
| 平衡 | 8.942 ms | 119 | 2.441 ms | 4.802 ms | 6.052 ms | 0 | 0 |
| 最佳能效 | 1.277 ms | 119 | 2.681 ms | 4.899 ms | 6.310 ms | 0 | 0 |

这里的指标仍从滚轮进入处理函数开始，到对应帧完成绘制结束。120 个消息产生 119 个绘制帧，说明没有因绘制阻塞而积压大量消息。

结果说明：

- 150 KB 文档在连续突发输入下没有出现超过 16.7 ms 或 50 ms 的长帧。
- 最佳能效模式仅比平衡模式 P95 慢约 2%，远低于常规冷启动和热打开的差异。
- 当前没有证据支持预布局、滚动降级、位图缓存或帧预算切块。
- 仍缺少“单个超大表格、超长代码块或复杂 flowchart 正好进入视口”的专项压力样例；只有在实际文档中复现出明显长帧时，才考虑低成本预布局。

复现：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command `
  "& '.\scripts\continuous-scroll-benchmark.ps1' -Events 120 -IntervalMs 0 `
   -Modes @('balanced','efficiency') -OutputName '150k-burst-check'"
```

原始结果位于 `build\continuous-scroll-results\150k-burst-max`。
