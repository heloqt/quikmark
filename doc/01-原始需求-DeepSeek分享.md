# Markdown 只读阅读面板 需求文档

## 1. 项目背景与目标

### 1.1 背景
AI 辅助编程普及后，大量需求、设计文档以 Markdown 形式产出，体量常见几十 K 到 200K，且需要**频繁打开、快速翻阅、来回切换**。现有方式各有短板：
- **VS Code 分栏预览**：挤占代码区、带编辑态 UI、上下文切换成本高；
- **再开一个编辑器/重型工具看文档**：重、启动慢、仍带编辑 UI；
- **浏览器打开 md**：依赖插件、样式不统一、带浏览器 chrome。

同时，基于 Electron/浏览器的工具在文档体量增大时打开和切换明显变慢（全文渲染 + 浏览器运行时架构）。

### 1.2 目标
做一个**纯原生、只读、面向双屏开发者的干净 Markdown 阅读面板**，同时满足两条并列硬目标：

**A. 干净阅读（形态主线）**
- 独立窗口，可常驻第二屏，不挤占编辑器。
- 纯阅读态：无编辑工具栏、无源码/预览切换、无侧边栏噪音。
- 多文档并排/快速切换，作为"参考屏"面板。
- 与编辑器、AI 工具形成"主屏写码 / 副屏看文档 / AI 对话"的三屏分工。

**B. 快（性能硬目标，不降级）**
- 中大型文档首屏可读在 **300ms 内**（冷启动）。
- 多文档切换 **<50ms**、无闪烁、保留滚动位置。
- 大文档滚动流畅（块级虚拟滚动）。
- 轻量：无浏览器内核，安装包小、可常驻。

**两条目标的关系**：干净是"为什么用它"，快是"为什么能一直开着、随切随看"。**速度不因"干净"而降级，反而因为要常驻而更关键。**

### 1.3 非目标（明确不做）
- 不做编辑器：无光标、无选区编辑、无撤销、无粘贴图片。
- 不做完整 GFM：公式、非 flowchart 类 Mermaid 以图片占位或不做。
- 不做插件、主题市场、云同步、双链、图谱。
- 不做任何**为丰富 UI 而损害干净/快**的功能（工具栏、侧栏、状态栏默认不做，除非证明不损害两目标）。
- 不做"和竞品对比"的市场工作。

### 1.4 平台与工具链
- **主目标平台**：Windows 10/11（Intel i3-12代档位为性能基准）。
- **构建工具链**：**MinGW-w64**（GCC），便于跨平台编译。
- **架构保持可移植**：核心（解析、布局、缓存、渲染抽象）与平台无关；wxWidgets 本身跨平台，为将来 Linux/macOS 适配留出空间，但**当前不承诺跨平台验收**。

### 1.5 性质
个人练手项目，目标是**验证 AI 编程在系统级桌面软件上的上限**，不以商业化为目的。

## 2. 使用场景与需求

### 2.1 典型场景
- 双屏开发者：主屏写代码，第二屏常驻阅读面板看设计/需求文档。
- 打开一份 100K–200K 的 AI 生成设计文档，**首屏 100–200ms 内可读**。
- 同时打开多个文档，**来回切换即时响应**，保留各自滚动位置。
- 打开 1–10MB 的大文档，**首屏可读 ≤300ms**，滚动流畅。
- 文档含基础 Markdown、表格、flowchart，能正确显示。

### 2.2 功能需求（按优先级）

| 优先级 | 需求 | 说明 |
|---|---|---|
| P0 | 打开并显示 Markdown | 基础语法：标题、段落、粗斜体、列表、引用、代码块、链接、图片、水平线 |
| P0 | 首屏快速可读 | 只渲染可见区 ± N 屏，其余占位 |
| P0 | 多文档打开与切换 | 模型常驻、布局缓存、切换保留滚动位置 |
| P0 | 基础滚动 | 滚动条高度估算、视口计算、按需布局绘制 |
| P0 | 干净阅读态 | 独立窗口、无编辑 UI、纯文档显示 |
| P1 | 表格显示 | 基础表格（简单列宽、单元格内换行），合并单元格二期 |
| P1 | flowchart 显示 | 解析 Mermaid flowchart + Graphviz 布局 + 绘制，布局结果缓存 |
| P1 | 图片显示 | 本地/相对路径图片，异步解码，占位 |
| P2 | 代码块高亮（可选） | 简单高亮或不做的取舍在实现时定 |
| P2 | 搜索（可选） | 二期，非 MVP |

### 2.3 非功能需求

| 项 | 指标 |
|---|---|
| 首屏可读（冷启动） | 100K–200K：**100–200ms**；1–10MB：**≤300ms** |
| 文档切换 | 目标 **<50ms**，无闪烁，保留滚动位置 |
| 滚动 | 大文档稳定流畅（目标 60fps） |
| 安装包 | 尽量小（无 Chromium，十几 MB 量级） |
| 内存 | 单文档 10MB 可接受；多文档 LRU 限制常驻 |
| 平台 | Windows 10/11 为主，MinGW-w64 构建，架构可移植 |
| 磁盘 | 兼容 NVMe / SATA SSD（机械盘不作保证） |

## 3. 技术路线

### 3.1 总体路线
**原生 C++ + wxWidgets，纯自研渲染，不内嵌浏览器，不执行 JS。MinGW-w64 构建。**

```
Markdown 源
  → 解析（md4c / cmark-gfm）→ 块级文档模型
  → 只对可见区 ± N 屏的块做布局
  → 用 wxDC / Cairo 绘制到视口
  → 布局结果与视口位图进缓存，供切换/滚动复用
```

### 3.2 关键选型

| 模块 | 选型 | 理由 |
|---|---|---|
| GUI 框架 | **wxWidgets** | 原生控件、轻量、C++、跨平台 |
| 构建工具链 | **MinGW-w64（GCC）** | 跨平台编译，Windows 主目标 |
| Markdown 解析 | **md4c**（备选 cmark-gfm） | C 库、快、可嵌入，解析与渲染解耦 |
| flowchart 布局 | **Graphviz（libgvc）** | 成熟分层布局，避免自写 Sugiyama |
| 绘制 | **wxDC**（优先）/ Cairo（如需矢量导出） | 与 wxWidgets 一致，可控 |
| 文字度量 | 系统字体 API + 缓存 | 避免重复度量 |
| 图片解码 | wxImage / 系统解码器 | 异步解码 + 占位 |

### 3.3 明确不采用
- **Electron / Qt WebEngine / wxWebView**：违背"轻量 + 原生 + 无 JS"目标。
- **自写 flowchart 分层布局**：成本过高，接 Graphviz。
- **公式 / 非 flowchart Mermaid 运行时渲染**：无 JS 引擎，二期仅图片占位。

### 3.4 核心设计原则
1. **块（Block）是一等公民**：段落/标题/列表/代码块/表格/flowchart/图片各为独立块，可独立布局、绘制、缓存。
2. **解析与布局分离**：解析全文（快），布局按需（只做可见区）。
3. **布局结果可缓存**：块布局结果、flowchart 坐标、视口位图都可存可取。
4. **重活异步**：解析可后台；flowchart 布局、图片解码、大表格列宽异步 + 占位。
5. **切换 = 换指针 + 重绘视口**：不重建控件，不重新解析。
6. **UI 做减法，性能做加法**：界面只保留文档；所有性能机制（视口渲染、布局缓存、异步）不可为简化实现而砍。
7. **核心可移植**：解析、布局、缓存、渲染抽象与平台无关，平台相关代码集中在 UI/绘制适配层。

## 4. 架构设计

### 4.1 模块划分

```
core/
  Document        持有源文本、块列表、滚动偏移；提供布局/绘制入口
  Block           块基类：layout(), paint(), height(), type()
    TextBlock       段落/标题/列表项/引用/代码块
    TableBlock      表格（自绘）
    FlowchartBlock  flowchart（Graphviz 布局 + 绘制）
    ImageBlock      图片（异步解码 + 占位）
  Parser          md4c 封装：源文本 → Block 列表
  LayoutEngine    块布局、高度估算、视口范围计算
  Renderer        渲染抽象（wxDC 实现，平台无关接口）
cache/
  DocumentCache   多文档常驻、切换、LRU 回收
  LayoutCache     块布局结果缓存（按文档/块 id）
  BitmapCache     视口位图缓存（LRU 限内存）
ui/
  MainWindow      主窗口、打开/切换/关闭
  DocumentView    视口、滚动条、滚动事件
  ScrollManager   滚动位置、高度估算修正
async/
  ParseWorker     后台解析（大文档）
  FlowchartWorker Graphviz 布局异步
  ImageWorker     图片解码异步
platform/
  字体度量、文件读取、高 DPI 等平台适配（当前 Windows 实现，接口可移植）
```

### 4.2 关键数据流

**打开文档**
```
读文件 → (后台)解析全文 → Block 列表
       → 布局可见区 ± N 屏（重块占位）
       → 绘制首屏 → 首屏可读 ✅
       → 异步：其余块按需、flowchart 布局、图片解码
```

**切换文档**
```
DocumentCache 取目标 Document（常驻则直接取）
  → 复用其 Block 列表与布局缓存
  → 恢复滚动偏移
  → 重绘视口（不重建控件、不重新解析）
```

**滚动**
```
滚动事件 → 计算新视口范围
  → 未布局块按需布局（高度估算 → 回填）
  → 只绘制可见块
  → 修正滚动条总高（平滑，避免跳动）
```

### 4.3 缓存策略
- **Block 布局结果**：全量可留（相对小）。
- **视口位图**：LRU 限制（内存敏感），切换快的关键是**布局缓存常驻**而非位图常驻。
- **文档常驻**：LRU，最多常驻 N 个全文 AST（如 2–3 个 10MB 文档），其余释放可重解析。
- **flowchart 布局坐标**：随文档缓存，切回不重跑 Graphviz。

## 5. 阶段拆分

### 阶段 0：架构骨架（约 1 周）
**交付**
- MinGW-w64 工程搭建（wxWidgets + md4c + Graphviz 接入）。
- `Document` / `Block` 基类 / `LayoutCache` 接口骨架（缓存可空实现）。
- 主窗口 + 空文档视图 + 渲染抽象接口。

**目的**：先立"块级抽象 + 缓存接口 + 渲染抽象"，避免后期重构，并保证核心可移植。
**AI 适用**：工程脚手架、基类定义、接口声明适合 AI 生成；**块抽象粒度需人工把关**。

---

### 阶段 1：解析 + 基础富文本绘制（MVP 前半，几周）
**交付**
- md4c 封装，源文本 → TextBlock 列表（标题/段落/列表/引用/代码块/链接）。
- TextBlock 的布局（断行、字体度量缓存）与绘制（wxDC）。
- 基础滚动 + 视口计算（只画可见块）。
- 预留 TableBlock / FlowchartBlock / ImageBlock 类型占位。

**验收**：单个 100K 文档可显示、可滚动；首屏可读进入 100–200ms 量级。
**AI 适用**：解析封装、绘制循环适合 AI；**断行/中英文混排/字体度量需人工写测试**。

---

### 阶段 2：多文档缓存 / 切换 / 回收（MVP 后半，约 1 周+）
**交付**
- `DocumentCache`：多文档常驻、切换、LRU 回收。
- 切换复用 Block 布局缓存，恢复滚动位置，只重绘视口。
- 位图缓存 + LRU 内存限制。

**验收（MVP 完成）**：打开 3–5 个 100K–200K 文档，来回切换 <50ms、无闪烁、滚动位置保留；界面保持纯阅读态。
**AI 适用**：缓存结构、LRU、切换状态机适合 AI；**缓存一致性、内存边界需人工测试**。

> **MVP = 阶段 1 + 阶段 2**：一个"干净、多文档流畅切换"的最小闭环。

---

### 阶段 3：表格自绘（完整版，1–2 周）
**交付**
- TableBlock 布局（列宽、行高、单元格内换行）与绘制。
- 起步范围：**无合并单元格、简单列宽分配**；合并单元格/复杂列宽二期。
- 表格布局结果进缓存。

**验收**：常见表格正确显示，滚动/切换不重算布局。
**AI 适用**：网格绘制适合 AI；**列宽分配、跨行高计算需人工把关**。

---

### 阶段 4：flowchart（完整版，1–2 周）
**交付**
- Mermaid flowchart 解析（节点、边、方向、子图基础）。
- 转 Graphviz 图 → libgvc 布局 → 取坐标。
- FlowchartBlock 绘制（矩形/箭头/文字）。
- 首屏 flowchart **先占位、异步布局替换**；布局结果缓存。

**验收**：常见 flowchart 正确显示；首屏含 flowchart 时首屏可读仍 ≤300ms（占位版）。
**AI 适用**：解析器、Graphviz 调用封装适合 AI；**坐标映射、占位高度估算、样式还原需人工**。

---

### 阶段 5：打磨与达标（持续）
**交付**
- 10MB 大文档路径：后台解析、视口渲染、高度估算修正、滚动条平滑。
- 性能埋点与调优：冷启动、首屏可读、切换、滚动帧率、内存。
- 边界语法打磨（嵌套、转义、复杂列表）。
- 平台适配层整理，为核心可移植打基础。

**验收**：见第 6 节指标。

## 6. 验收标准

### 6.1 干净线（人工走查 + 用例）

| 项 | 标准 |
|---|---|
| 纯阅读态 | 打开即文档，无编辑工具栏/源码切换/侧边栏 |
| 独立常驻 | 可独立窗口置于第二屏，不依附编辑器 |
| 多文档 | 可并排/快速切换多份文档 |
| 视觉噪音 | 除文档与必要滚动条外，无多余 UI |

### 6.2 快线（埋点数据）

| 项 | 标准 | 测量方式 |
|---|---|---|
| 首屏可读（冷启动） | 100K–200K：≤200ms；1–10MB：≤300ms | 埋点：进程启动→首屏可读 |
| 文档切换 | <50ms，无闪烁，滚动位置保留 | 埋点多文档切换 |
| 滚动 | 大文档流畅（目标 60fps） | 帧率埋点 |
| 内存 | 单文档 10MB 可接受；多文档 LRU 生效 | 内存峰值监控 |
| 轻量 | 无 Chromium，安装包十几 MB 量级 | 安装包体积检查 |
| 稳定性 | 反复打开/切换/滚动无崩溃、无内存泄漏 | 长时运行测试 |

**关键定义**：300ms 指"**冷启动到首屏可见区可读**"，不含全文布局/绘制；flowchart 就绪可晚于 300ms（占位可接受）。**两条线都过才算达标。**

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 断行/字体度量慢或不一致 | 首屏慢、排版怪 | 度量缓存；先简单换行，复杂禁则二期 |
| 高度估算不准 | 滚动条跳动 | 估算 + 布局后平滑修正；占位高度尽量准 |
| 首屏含大 flowchart 同步布局 | 首屏超 300ms | 占位 + 异步替换 |
| 多文档缓存内存失控 | 内存涨 | LRU 限制 AST/位图常驻 |
| 跨块选区/命中测试复杂 | 只读下可简化 | MVP 不做选区；命中测试仅用于滚动定位 |
| Graphviz 依赖/编译（MinGW） | 构建麻烦 | 预编译 MinGW 版库或源码集成，锁定验证 |
| **UI 膨胀** | **同时损害干净和快** | 工具栏/侧栏/状态栏默认不做，评审拦截 |
| AI 生成布局代码边界错误 | 难排查 | 布局/估算/缓存一致性**人工写测试用例** |
| MinGW 与平台差异 | 字体度量/DPI 行为差异 | 平台适配层隔离，Windows 优先验证 |

## 8. AI 编程适用性标注（练手关注点）

| 模块 | AI 生成适合度 | 人工必须把关 |
|---|---|---|
| 工程脚手架、基类、接口声明 | 高 | 块抽象粒度 |
| md4c 封装、AST→Block 转换 | 高 | 边界语法用例 |
| 绘制循环、网格绘制 | 高 | 裁剪与性能 |
| 缓存结构、LRU、切换状态机 | 中高 | 一致性、内存边界 |
| 断行、字体度量、列宽分配 | **低** | **必须人工写测试** |
| 滚动高度估算与修正 | **低** | **必须人工写测试** |
| Graphviz 调用、坐标映射 | 中 | 占位高度、样式还原 |

**结论**：AI 适合"结构清晰、可测试"的部分；**布局算法、估算、缓存一致性是 AI 的重灾区，需人工写用例兜底**——这正是本项目要验证的边界。
