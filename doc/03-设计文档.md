## 1. 设计目标

设计必须同时支撑以下目标：

1. 不依赖浏览器内核和 JavaScript 运行时。
2. 冷启动后尽快显示首个可见区域的文本，不等待全文布局完成。
3. 多文档切换复用已有模型和布局，避免重新解析。
4. 大文档只绘制可见区域，滚动时按需布局。
5. 核心解析、布局、缓存和渲染抽象不与 Windows 强绑定。
6. 首版界面少而克制，常驻 UI 仅保留文档视图和必要滚动条。
7. 性能机制不能被“先简化实现”的理由移除。

## 2. 关键技术决策

| 编号 | 决策 | 理由 | 备注 |
|---|---|---|---|
| ADR-001 | 使用原生 C++ 开发 | 满足轻量、原生和性能目标 | C++ 标准版本待工程初始化时确认 |
| ADR-002 | GUI 使用 wxWidgets | C++、轻量、跨平台，原生控件能力足够 | 当前只验收 Windows |
| ADR-003 | 构建使用 MinGW-w64（GCC） | 满足指定工具链和未来可移植方向 | 依赖的 MinGW 构建产物需锁定 |
| ADR-004 | Markdown 解析首选 md4c，cmark-gfm 为备选 | C 实现、速度快、易于嵌入 | 只有 md4c 无法满足边界能力时才切换 |
| ADR-005 | 使用自研块级布局与渲染 | 避免 Web 渲染栈，支持按需布局 | 不使用 wxWebView |
| ADR-006 | 绘制优先使用 wxDC | 与 wxWidgets 统一，首版依赖更少 | Cairo 仅在有明确导出需求时评估 |
| ADR-007 | flowchart 使用 Graphviz/libgvc 布局 | 避免自写 Sugiyama 分层布局 | 需要验证 MinGW 构建和线程安全 |
| ADR-008 | 解析结果采用不可变块模型 | 便于缓存、跨线程传递和视图切换 | 可变布局结果不直接写回共享文档 |
| ADR-009 | 文档、布局和位图分别缓存 | 分别控制命中率、失效范围和内存 | 首版可先实现布局缓存和文档缓存 |
| ADR-010 | 解析、flowchart、图片等重任务异步执行 | 保证首屏和交互响应 | 所有 wx 绘制仍只在主线程执行 |

明确不采用 Electron、Qt WebEngine、wxWebView、Node/JavaScript 渲染链路，也不自研 flowchart 分层布局算法。

## 5. 核心数据模型

### 5.1 Document

`Document` 表示一个打开的文件及其解析结果：

- 稳定文档标识。
- 文件路径、显示标题和文件元信息。
- 源文本或可重新读取源文本的引用。
- 块列表或块树。
- 解析状态：未开始、进行中、首屏可用、完成、失败。
- 每份文档独立的阅读状态，例如滚动偏移和当前视口锚点。

解析完成后的块结构被视为不可变。布局缓存、图片结果和 flowchart 坐标放在独立缓存中，避免多个视图同时读写共享文档。

### 5.2 Block

块是布局、绘制和缓存的基本单位。建议接口语义如下：

```cpp
enum class BlockKind {
  Text,
  Table,
  Image,
  Flowchart
};

struct LayoutContext {
  float contentWidth;
  float dpiScale;
  FontSet fonts;
};

struct BlockLayout {
  float estimatedHeight;
  float finalHeight;
  bool heightIsFinal;
  std::uint64_t layoutVersion;
};

class Block {
public:
  virtual ~Block() = default;
  virtual BlockId id() const = 0;
  virtual BlockKind kind() const = 0;
  virtual float estimateHeight(const LayoutContext&) const = 0;
  virtual float layout(const LayoutContext&) = 0;
  virtual void paint(Painter&, const RectF& viewport) const = 0;
};
```

实际接口可调整，但必须满足：

- 块可以独立布局和绘制。
- 布局结果可以按块缓存。
- 首屏可先使用估算高度。
- 绘制只处理与视口相交的范围。

### 5.3 块类型

| 类型 | 职责 | 首版范围 |
|---|---|---|
| TextBlock | 标题、段落、列表、引用、代码块、水平线 | MVP |
| TableBlock | 基础表格的列宽、行高、单元格内换行和网格绘制 | 完成版 |
| ImageBlock | 加载图片、异步解码、尺寸计算、占位和降级 | 完成版 |
| FlowchartBlock | flowchart 解析结果、Graphviz 坐标、节点和连线绘制 | 完成版 |

`TextBlock` 不应只保存纯字符串。粗体、斜体、链接和代码等行内样式应保存为有序 `InlineSpan` 列表，布局阶段再换算为具体字体和绘制指令。

### 5.4 文档与视图状态分离

| 状态 | 归属 | 生命周期 |
|---|---|---|
| 源文本、块结构 | Document | 文档缓存期间 |
| 块布局结果 | LayoutCache | 与文档和布局条件相关 |
| 滚动位置、视口锚点 | DocumentViewState | 文档打开期间 |
| 当前活动文档 | SessionController | 应用运行期间 |
| 位图、flowchart 坐标 | 独立缓存 | 受 LRU 和内存预算控制 |

这种分离保证切换文档时只更换当前状态和绘制来源，不重建窗口控件。

## 6. Markdown 解析

### 6.1 解析流程

```text
文件读取
  → md4c 逐步扫描与回调
  → BlockBuilder 生成不可变块
  → 小批次发送到 UI
  → 首批块触发首屏布局与绘制
  → 后台继续解析直至全文完成
```

md4c 的块回调天然按文档顺序产生结果。对于大文档，不等待“全部回调结束”再显示，而是将前几批块尽快交给 UI。首批块的数量应覆盖首屏和适量 overscan，不宜按字节硬编码。

### 6.2 解析约束

- 每个块分配稳定 `BlockId`，供布局缓存和异步结果回填使用。
- 回调中不直接调用 wxWidgets 绘制接口。
- 解析批次应有合并机制，避免每个块触发一次 UI 事件。
- 失败或取消解析时，已经显示的部分内容可保留，同时提示文档未完整解析。
- 不同文档和不同解析版本之间不能复用块缓存。
- Markdown 边界语法以人工维护的用例集验证，特别是嵌套列表、转义字符、围栏代码块和中英文混排。

### 6.3 基础语法映射

| Markdown 结构 | 中间模型 |
|---|---|
| 标题 | 带标题级别的 TextBlock |
| 段落 | TextBlock + InlineSpan |
| 粗体/斜体/链接/行内代码 | InlineSpan 样式 |
| 有序/无序/任务列表 | 列表信息 + TextBlock |
| 引用 | 引用层级信息 + TextBlock |
| 围栏/缩进代码块 | 等宽字体 TextBlock |
| 水平线 | 独立轻量 Block 或 TextBlock 变体 |
| 表格 | TableBlock |
| 图片 | ImageBlock |
| Mermaid flowchart 围栏 | FlowchartBlock |

具体 md4c 回调到模型的映射，后续在详细设计中逐项列出。

## 7. 布局与滚动

### 7.1 按需布局

布局只覆盖以下范围：

```text
当前视口 + 前后各 N 屏 overscan
```

N 作为可调参数，初始可取 1–2 屏。首屏先绘制文本块；表格、图片和 flowchart 使用估算高度占位，异步完成后替换。

布局必须考虑：

- 内容区宽度。
- DPI 缩放。
- 字体集合和字号。
- 行内样式。
- 段落间距、标题间距、列表缩进和引用缩进。
- 代码块是否横向滚动。
- 中英文混排、断词和标点换行规则。

### 7.2 块高度与滚动条

首屏时不可能知道全部块的最终高度，因此需要“估算 + 修正”机制：

1. 每个块给出基于宽度、字号和内容类型的估算高度。
2. 一个块级索引维护累计估算高度和总高度。
3. 块完成布局后，将估算值修正为最终值。
4. 滚动条范围随修正更新。
5. 为减少可视跳变，优先保持当前视口锚点稳定。

建议实现一个支持 `O(log n)` 高度更新的块级累计索引，例如 Fenwick tree；如果基准测试证明普通前缀数组足够，可以简化。该选择应在性能原型中验证。

### 7.3 绘制

每帧只遍历与视口相交的块，并执行：

1. 对未布局块按需布局。
2. 计算需要裁剪的区域。
3. 通过 `Painter` 绘制文本、边框、代码背景、图片和 flowchart。
4. 在可用时使用双缓冲，减少闪烁。

布局和 `wxDC` 绘制都应在 UI 主线程执行，或者至少保证所有 wx 绘制对象只在主线程访问。解析、图片解码和 Graphviz 布局在后台完成后，通过事件队列把不可变结果送回主线程。

## 8. 缓存设计

### 8.1 DocumentCache

- 按最近使用顺序管理已打开文档。
- 同时受文档数量和总内存预算限制。
- 目标可常驻约 2–3 份 10 MB 文档，最终数量由基准测试决定。
- 被回收的文档释放解析块和关联缓存；再次打开时可重新解析。
- 当前活动文档不可被回收。

### 8.2 LayoutCache

布局缓存键至少包含：

```text
documentId + blockId + contentVersion + layoutVersion
+ contentWidth + dpiScale + fontConfiguration
```

窗口宽度或 DPI 变化时，文本换行和高度可能变化，不能继续使用旧布局。可采用按条件分区清理，避免切换 DPI 时污染新结果。

### 8.3 BitmapCache

- 对难以快速重绘的视口或块位图做 LRU 缓存。
- 位图缓存不是切换速度的唯一来源，布局缓存命中更重要。
- 必须设置字节级预算，避免高 DPI 下位图迅速占满内存。
- MVP 可以先不实现，完成基础性能测量后再投入。

### 8.4 FlowchartCache

- 按文档、块、源内容摘要和布局配置缓存节点坐标、边路径和画布尺寸。
- 文档仍常驻时，切回不重新运行 Graphviz。
- 字体、DPI 或布局参数变化时失效。

## 9. 多文档切换

切换流程基线：

```text
接收切换请求
  → 从 DocumentCache 获取目标 Document
  → 取消或标记当前可丢弃任务
  → 恢复目标文档的滚动锚点
  → 复用已命中的块布局
  → 对目标视口缺失布局的块按需布局
  → 重绘视口
```

不执行以下动作：

- 不销毁并重建文档控件。
- 不清空整个文档模型。
- 不重新解析已完成的文档。
- 不重新计算已命中的表格和 flowchart 布局。

`<50 ms` 是对已打开且模型常驻文档的目标。文档被 LRU 回收后重新打开，应视为打开操作，而不是热切换。

## 10. 并发与任务管理

### 10.1 线程职责

| 执行位置 | 职责 |
|---|---|
| UI 主线程 | 窗口事件、视图状态、wxDC 绘制、字体度量、同步布局 |
| ParseWorker | 文件解析和块构建 |
| FlowchartWorker | Mermaid flowchart 解析和 Graphviz 布局 |
| ImageWorker | 图片加载与解码 |
| 后台线程 | 缓存清理、非关键统计，后续按需增加 |

### 10.2 任务规则

- 跨线程只传递值对象或不可变对象。
- 每个异步结果携带 `documentId`、`blockId` 和 generation，主线程丢弃过期结果。
- 文档关闭或切换后，已排队但尚未开始的任务应取消。
- flowchart 调用 libgvc 时先使用单一专用 worker 串行执行，避免未经验证的全局状态竞争。
- 所有性能埋点记录统一时钟源和阶段边界。

### 10.3 缓存一致性

块内容、布局版本和异步结果必须成套校验。不能仅以块序号作为缓存键，否则增量解析、编辑后重开或重排后可能错位。

## 11. 渲染抽象

建议定义与 wxWidgets 解耦的最小绘制接口：

```cpp
class Painter {
public:
  virtual ~Painter() = default;
  virtual void setClip(const RectF&) = 0;
  virtual void drawText(const TextRun&, const PointF&) = 0;
  virtual void drawRect(const RectF&, const PaintStyle&) = 0;
  virtual void drawLine(const PointF&, const PointF&, const PaintStyle&) = 0;
  virtual void drawImage(const ImageHandle&, const RectF&) = 0;
};

class TextMetrics {
public:
  virtual ~TextMetrics() = default;
  virtual SizeF measure(const TextStyle&, std::string_view) = 0;
  virtual std::vector<int> breakLines(
      const TextStyle&, std::string_view, float maxWidth) = 0;
};
```

首版由 wxWidgets 平台适配层实现，Cairo 不作为初始依赖。渲染接口需要支持裁剪、坐标系、DPI 缩放和颜色语义，具体 API 在性能原型中调整。

## 12. 专用块设计

### 12.1 表格

首版表格布局步骤：

1. 解析各列内容并测量最小/自然宽度。
2. 在可用宽度内分配列宽。
3. 对单元格内文本进行换行。
4. 计算每行高度和整表高度。
5. 缓存布局并绘制网格和文本。

首版明确不处理或仅降级处理：

- 跨行、跨列合并单元格。
- 极复杂列宽分配。
- 超宽表格的横向交互细节。

### 12.2 图片

- 相对路径以 Markdown 文档所在目录为解析基准，需在需求确认后固定。
- 先以已知或默认尺寸显示占位。
- 后台解码完成后更新尺寸，并平滑修正文档总高度。
- 解码失败显示稳定降级占位，不阻塞其他块。
- 图片缓存受字节预算控制。

### 12.3 Mermaid flowchart

处理链路：

```text
flowchart 源码
  → 白名单语法解析
  → 转换为 Graphviz 图
  → libgvc 计算坐标与路径
  → 转换到文档坐标系
  → Block 自绘节点、文字、箭头
```

设计要点：

- 只支持明确的 flowchart 子集，不承诺完整 Mermaid。
- 首次绘制先使用占位高度，布局完成后替换。
- 坐标结果随文档缓存。
- Graphviz 的字体配置、边距和 DPI 必须与最终绘制环境一致。
- 若 MinGW 下 libgvc 的构建或线程行为不可控，需要重新评估集成方式，但不改变“先占位、异步替换”的用户体验目标。

## 13. 界面设计基线

首版窗口只包含：

- Markdown 文档视图。
- 必要时的垂直滚动条。
- 在大文档中按需出现的水平滚动或表格区域。

默认不包含：

- 编辑工具栏。
- 源码/预览切换。
- 常驻文件树或大纲侧栏。
- 常驻状态栏。
- 多标签页工具条。

文件打开、文档切换和关闭必须有可达入口，但原文未指定具体交互。后续需在需求细化中确定使用原生菜单、快捷键、临时浮层还是最小标签入口。任何入口都应保持常驻视觉噪声最低。

“多文档并排”尚未明确是否属于 MVP。本设计基线先支持快速切换和独立滚动状态，同窗分栏留待需求确认后扩展。

## 14. 性能设计

### 14.1 性能路径

首屏关键路径只包含：

```text
进程启动
 → 打开文件
 → 读取首批内容
 → 解析出足够覆盖首屏的块
 → 完成这些块的布局
 → 绘制首屏
```

以下工作应移出首屏关键路径：

- 全文解析完成通知。
- 非可见区块的精确布局。
- 图片解码。
- flowchart 解析和 Graphviz 布局。
- 位图预热。
- 缓存持久化。

### 14.2 埋点阶段

| 事件 | 含义 |
|---|---|
| `process_start` | 进程开始 |
| `open_requested` | 收到打开文件请求 |
| `file_opened` | 文件读取完成或首批字节可用 |
| `first_blocks_ready` | 首批块可交给 UI |
| `first_viewport_layout_ready` | 首屏布局完成 |
| `first_viewport_painted` | 首屏完成绘制 |
| `documents_switched` | 目标文档首次呈现 |
| `scroll_frame` | 单帧滚动耗时 |
| `heavy_block_ready` | 图片、表格或 flowchart 就绪 |
| `cache_hit` / `cache_miss` | 缓存命中情况 |
| `memory_sampled` | 文档、布局、位图等内存占用 |

### 14.3 基准语料

至少准备以下测试文件：

| 类型 | 规模 |
|---|---|
| 中英混排普通文档 | 100 KB、200 KB、1 MB |
| 长代码块和复杂列表 | 1 MB、10 MB |
| 多表格文档 | 100 KB、1 MB |
| 多图片文档 | 100 KB、1 MB |
| 含 flowchart 文档 | 100 KB、1 MB |
| 极端边界文档 | 空文件、长单行、深嵌套、损坏文件 |

性能基准在 Windows 10/11、SSD、Intel i3-12 代档位设备上执行，并记录硬件、构建类型和首次/热运行条件。

## 15. 测试策略

| 层级 | 重点 |
|---|---|
| 单元测试 | 块构建、行内样式、断行、高度估算、缓存键、LRU、滚动锚点 |
| 集成测试 | 打开、切换、滚动、关闭、部分解析、异步结果回填 |
| 视觉测试 | 标题、列表、引用、代码块、表格、图片、flowchart 的固定样例 |
| 性能测试 | 首屏、切换、滚动帧率、内存峰值、包体 |
| 稳定性测试 | 长时间反复打开/切换/滚动，检查崩溃和泄漏 |
| 跨平台结构检查 | 核心目录不得引用平台或 wxWidgets UI 类型 |

重点人工测试：

- 中英文混排和标点换行。
- 字体度量缓存命中与失效。
- 高度估算修正时滚动条是否跳动。
- 异步结果晚到、文档已切换或关闭时的处理。
- DPI 变化和窗口宽度变化。
- 缓存回收后重新打开文档。
- libgvc 集成和含 flowchart 文档的首屏表现。

## 16. 阶段落地

| 阶段 | 设计工作 | 退出条件 |
|---|---|---|
| M0 架构骨架 | 工程目录、核心接口、Painter、空窗口 | MinGW-w64 可构建运行；核心层不依赖 UI |
| MVP 前半 | md4c 解析、TextBlock、布局、可见区绘制、滚动 | 100 KB 文档可读、可滚动，首屏达到目标量级 |
| MVP 后半 | DocumentCache、LayoutCache、切换状态和 LRU | 3–5 份文档切换小于 50 ms，滚动位置保留 |
| 完成版 | 表格、图片、flowchart | P1 基础能力通过视觉和交互验收 |
| 达标 | 10 MB 路径、埋点、调优、稳定性和可移植整理 | 需求文档第 8 节两条验收线均通过 |

## 17. 风险与验证顺序

| 风险 | 优先验证方式 |
|---|---|
| md4c 增量回调无法及时产生首屏块 | 用 1 MB 和 10 MB 文件做解析时间线原型 |
| 字体度量成为布局瓶颈 | 测量不同字号的缓存命中率和首屏布局耗时 |
| 高度修正导致滚动条跳动 | 构造高度差异大的混合文档做滚动测试 |
| wxDC 在高 DPI 下裁剪/位图行为不一致 | Windows 100%/125%/150%/200% DPI 测试 |
| Graphviz 在 MinGW 下构建困难 | M0 阶段完成最小 libgvc 链接和布局样例 |
| libgvc 存在线程安全问题 | 使用专用串行 worker，并做并发压力验证 |
| 文档和位图缓存造成内存失控 | 设置字节预算，进行 3–5 文档和 10 MB 文档压力测试 |
| 异步结果回填错位 | 使用稳定 BlockId、generation 和完整缓存键 |
| UI 入口破坏纯净阅读 | 先确定最小打开/切换交互，再做视觉走查 |

建议先完成三个技术原型，再进入完整 UI：

1. MinGW-w64 + wxWidgets + md4c 的最小可运行窗口。
2. 10 MB 文档的首批块解析、首屏布局和绘制时间线。
3. MinGW-w64 + libgvc 的最小 flowchart 布局与坐标读取。

## 18. 待确认的设计问题

1. MVP 的“多文档并排”是否为主窗口分栏，还是允许通过快速切换满足。
2. 文件打开和文档切换的具体交互入口。
3. 是否持久化最近文档、窗口位置和每文档滚动位置。
4. 大文档解析失败时的交互，以及是否保留已解析部分。
5. 文本选择是否完全不做；原文仅明确不编辑，但未明确是否允许复制。
6. 外链和相对链接的打开策略。
7. 表格首个版本的列宽算法、超宽处理和无合并单元格限制。
8. Mermaid flowchart 的子集语法白名单。
9. 缓存总内存预算、文档常驻数量和位图预算。
10. 文件编码与超大文件上限。
11. Cairo 是否永远不引入，还是仅在后续导出功能需要时引入。
12. 发布包体上限和安装方式。

这些问题解决后，再编写文件级详细设计、关键接口签名、任务状态机和性能测试清单。

## 19. 变更规则

- 改变用户可见能力时，先更新需求文档，再更新本设计文档。
- 改变首屏、切换、滚动或内存路径时，必须记录设计原因和新的验证方法。
- 技术选型变化应新增决策记录，不能只删除旧结论而丢失背景。
- 所有性能指标必须对应可复现的测试文件、硬件环境和测量阶段。
