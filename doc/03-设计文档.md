## 1. 设计结论摘要

核心技术路线确定为：

- 原生 C++17、wxWidgets 3.3、md4c 和自研块级 Markdown 渲染。
- 一个进程、一个主窗口、多个文档 Tab，共用一个文档视图。
- 每个 Tab 持有独立文档模型、解析状态、滚动锚点和文件监控状态。
- 单实例通过命名互斥量和本用户会话内命名管道转发文件路径。
- 文件变化只提示，不自动替换正在阅读的内容。
- 解析、解码和 flowchart 分析异步执行；wxWidgets UI 和 `wxDC` 只在主线程使用。
- 文档内容不可变，布局结果独立缓存，不在 Block 内保存可变布局状态。
- 可视区按需布局，使用块高度索引和阅读锚点修正滚动位置。
- 首版不缓存整屏位图，只保留一个当前帧后备缓冲。
- 不引入 Graphviz 和 Cairo。基础 flowchart 使用受限语法和自研分层 DAG 布局。
- P1 支持跨块纯文本选择与复制，不实现富文本剪贴板格式。
- P1 支持跟随系统、浅色和暗色三种外观模式。
- 主发布制品使用安装器形式，最终用户下载文件必须小于 10 MB。

## 2. 对原设计的复核结论

| 原设计 | 问题 | 新决策 |
|---|---|---|
| 只有 DocumentView，没有 Tab、单实例和文件转发设计 | 与需求 v1.0 直接冲突 | 增加 TabSession、TabStrip、SingletonGuard 和 IPC 命令通道 |
| Block 被描述为不可变，但 `layout()` 会修改 Block | 模型与缓存、并发边界自相矛盾 | Block 内容不可变；布局结果由 LayoutEngine 单独生成并进入缓存 |
| 依赖 md4c 的块回调尽快产生首屏内容 | 超大单段落、超长代码块可能直到接近文件末尾才闭合 | 增加流式块构建，超长开放块可按安全文本边界拆成连续片段 |
| 对视口或块做 BitmapCache | 高 DPI 下内存代价大，且布局命中率才是切换性能关键 | v1 不缓存整屏位图，只保留当前帧后备缓冲 |
| 使用 Graphviz/libgvc 绘制基础 flowchart | 依赖大、MinGW 构建复杂、全局线程状态风险高，与 <10 MB 冲突 | 定义受限 flowchart 子集，使用自研分层 DAG 布局；不支持时降级源码 |
| MVP 不做文本选择，但 P1 要求复制 | 没有行级文本映射，P1 再补会影响布局和命中测试 | P0 数据模型保留 TextPosition 和行文本范围，P1 实现跨块选择 |
| DocumentCache 使用 LRU 管理“已打开文档” | 已打开 Tab 被回收会导致切换时重新解析，不符合 Tab 语义 | Tab 始终保留；仅在内存软预算超限时卸载非活动文档内容 |
| “核心可移植”但布局直接依赖 wx 字体度量 | 核心边界不够清楚 | 引入 TextEngine 和 Painter 抽象，平台实现集中在 wx/Windows 层 |
| 文件打开入口、文件关联、拖入和重复打开未闭合 | 无法实现单窗口 Tab 行为 | 建立统一 OpenRequest 流程，所有入口进入同一去重和 Tab 激活逻辑 |
| 性能指标混有挑战目标和验收入口 | 容易把 10 MB 挑战项误当硬门槛 | 只把 P0 热打开 300 ms 作为验收；10 MB 冷启动只记录结果 |
| 未定义发布方式和依赖处理 | 无法提前控制 <10 MB | 固定 Windows x64 安装器、静态自包含依赖、禁止 UPX |

## 3. 范围与约束

### 3.1 P0 范围

- 打开本地 Markdown，支持文件菜单、资源管理器关联、拖入和命令行路径。
- 单窗口多 Tab；同一文件只保留一个 Tab。
- UTF-8 和 UTF-8 BOM。
- 基础 Markdown：标题、段落、强调、列表、引用、代码块、链接、图片占位、水平线。
- 文件变化检测，非模态提示，确认后重载。
- 单实例窗口和文件路径转发。
- 可见区按需绘制、长文档滚动、Tab 阅读位置恢复。
- 100 KB–200 KB 文档热打开不超过 300 ms。

### 3.2 P1 范围

- 基础表格。
- 本地、相对路径及 HTTP/HTTPS 网络图片。
- Mermaid flowchart 基础子集。
- 跨块纯文本选择与复制。
- `http`、`https`、`mailto` 外部链接使用系统默认应用打开。
- 默认跟随系统主题，并支持浅色、暗色即时切换和偏好保存。
- 明确并验收普通首屏、Tab 切换和滚动指标。

### 3.3 非目标

- 编辑、保存和撤销。
- 同窗分栏。
- 完整 GFM、完整 Mermaid 和公式渲染。
- 自定义配色、主题市场、插件、云同步、双链和知识图谱。
- Linux/macOS 验收。
- 内部锚点跳转、最近文档和窗口状态恢复属于 P2。
- `data:`、`file:` 和 `ftp:` 等其他图片协议。

## 4. 技术选型

| 编号 | 类别 | 选择 | 结论 |
|---|---|---|---|
| ADR-001 | 语言 | C++17 | 使用 `filesystem`、`string_view`、`variant` 已足够，避免不必要的标准版本要求 |
| ADR-002 | 编译目标 | Windows 10/11 x64 | 首版不维护 32 位和 ARM64 构建 |
| ADR-003 | 工具链 | MinGW-w64，UCRT 运行时 | 与目标系统一致；发行版中静态链接必要运行时 |
| ADR-004 | 构建 | CMake + Ninja | 统一 IDE 和命令行构建，不绑定专有工程文件 |
| ADR-005 | GUI | wxWidgets 3.3 Unicode | 原生窗口、菜单、剪贴板和文件对话框，使用其系统主题与暗色模式支持 |
| ADR-006 | Markdown | md4c | 嵌入式 C 解析器，支持所需 GFM 扩展；固定并记录版本 |
| ADR-007 | 渲染 | wxWidgets 绘制 API + 自研布局 | 不引入 WebView、Electron 或浏览器运行时 |
| ADR-008 | 绘图后端 | `wxDC` / `wxAutoBufferedPaintDC` | 首版不引入 Cairo，避免额外依赖和坐标差异 |
| ADR-009 | flowchart | 受限解析器 + 自研分层 DAG 布局 | 避免 Graphviz 依赖；不支持语法直接降级原始代码 |
| ADR-010 | 文件监听 | wxFileSystemWatcher 封装 | Windows 下使用系统文件通知；统一对上层发文件变化信号 |
| ADR-011 | 单实例 | 命名互斥量 + 本用户命名管道 | 能转发多个文件路径，不依赖窗口消息查找 |
| ADR-012 | 发布 | 单个 Windows 安装器 | 负责文件关联、卸载和运行库部署；便携包非当前必备交付 |
| ADR-013 | 主题 | 系统跟随 + 显式浅色/暗色覆盖 | 覆盖三种模式，手动选择跨启动保存；只改变颜色，不改变排版尺寸 |

第三方依赖必须在仓库中锁定版本或提交哈希。构建过程不能在发布时临时下载未知版本。

## 7. 应用生命周期与单实例

### 7.1 启动流程

```text
进程启动
  → 解析命令行中的文件路径
  → 获取本用户会话单实例锁
      ├─ 获得锁：成为主实例，创建 IPC Server 和主窗口
      └─ 未获得锁：成为次实例，连接主实例并发送路径后退出
  → 主实例将收到的路径转换为 OpenRequest
  → 窗口和 TabManager 处理 OpenRequest
```

### 7.2 单实例规则

- 使用本用户会话内唯一命名互斥量决定主实例。
- 使用本用户会话内命名管道转发打开请求。
- 同名 IPC 对象必须限制在当前登录用户的安全边界内。
- 次实例发送后立即退出，不创建隐藏主窗口。
- 主实例未运行或异常退出时，操作系统释放互斥量，下一次启动可正常成为主实例。
- 次实例连接主实例超时，应显示启动失败提示并退出，不创建第二个主窗口。
- 管理员权限与普通权限实例之间的互通不纳入 P0 验收。
- 主实例收到没有文件路径的第二次启动时，只恢复并激活已有窗口。

### 7.3 统一打开请求

菜单选择、资源管理器关联、拖入、命令行和 IPC 最终都转换为：

```text
OpenRequest {
  vector<absolute_path>,
  source: menu | association | drop | command_line | ipc
}
```

处理顺序：

1. 转换为绝对路径并规范化。
2. Windows 路径比较采用大小写不敏感规则。
3. 已存在同一规范路径的 Tab 时，只激活已有 Tab。
4. 不存在时创建新 Tab，并显示加载状态。
5. 文件读取或编码校验失败时不创建空白重复 Tab。
6. 多文件请求按输入顺序逐个建立或激活 Tab。
7. 全部处理完成后激活最后一个有效文档。

## 8. Tab 与阅读状态

### 8.1 TabSession

每个 `TabSession` 至少包含：

- Tab 唯一标识。
- 规范化文件路径。
- 当前 Document generation。
- 文档模型和解析状态。
- 独立滚动锚点。
- 文件变化状态。
- 该文档关联的异步任务代次。

同一文件不创建第二个 `TabSession`。

### 8.2 视图复用

主窗口只创建一个 `DocumentView`。Tab 切换时更换它引用的 `OpenDocument` 和 `ViewState`，不销毁并重建文档控件。

TabStrip 单独负责：

- 显示文件名和活动状态。
- 关闭按钮。
- 文件已变化标记。
- 点击、中键关闭和键盘切换。
- 内容超出时滚动 Tab 条。

### 8.3 Tab 生命周期

- `Ctrl+O` 打开文件。
- `Ctrl+W` 关闭当前 Tab。
- `Ctrl+Tab` 切换下一个 Tab。
- `Ctrl+R` 重新加载当前文档。
- 关闭 Tab 时取消解析、解码和 flowchart 任务，并停止文件监控。
- 关闭最后一个 Tab 时关闭主窗口。
- 关闭窗口时先取消全部后台任务，再释放文档和缓存。

## 9. 文件读取、编码与错误处理

### 9.1 编码

- 内部统一使用 UTF-8。
- 文件开头存在 UTF-8 BOM 时去除 BOM，再进入解析器。
- 对字节流执行严格 UTF-8 校验。
- 遇到非法 UTF-8 时停止渲染，显示“文件编码不受支持或内容已损坏”，不把乱码注入文档模型。
- 当前不支持 UTF-16、GBK、GB18030 等编码，也不做自动编码猜测。

### 9.2 文件大小

- 10 MB 文档属于需求保证范围。
- 为保护进程，设置 64 MiB 安全上限。
- 超过安全上限时保留 Tab 路径信息，但显示文件过大提示，不读取到文档模型。
- 安全上限是防崩溃措施，不扩大需求中的 10 MB 保证范围。

### 9.3 错误状态

| 场景 | 处理 |
|---|---|
| 文件不存在或无权限 | 新 Tab 显示失败状态，保留可读菜单入口；已有 Tab 保留原内容 |
| 非法 UTF-8 | 显示明确错误，不渲染乱码 |
| 超过安全大小 | 显示“文件过大”，不尝试全量解析 |
| 解析中途失败 | 保留已经完成的块，顶部显示非模态错误提示 |
| 文件被删除或改名 | 保留最后内容，显示文件已不可用提示 |
| 重新加载失败 | 原子回退到旧 generation，不替换当前可读内容 |

错误提示使用文档区域内的非模态提示条，不新增常驻状态栏。

## 10. 文件变化检测与重载

### 10.1 检测

- 每个已打开 Tab 监控其所在目录，并过滤对应的规范文件路径。
- 修改、替换、删除和改名事件都转换为统一 `FileChanged` 信号。
- 对短时间连续事件进行合并，文件停止变化约 300 ms 后再提示。
- 没有收到系统通知时，不保证立即发现变化；手动重载始终可用。

### 10.2 提示

- 当前 Tab：显示非模态“文件已在外部修改，重新加载”提示。
- 非当前 Tab：在 Tab 上显示变化标记，不主动切换或弹窗。
- 文件连续变化时只更新待处理状态，不重复堆积提示。
- 自动重载默认关闭，仅作为 P2 可选项。

### 10.3 重载事务

```text
用户确认重载
  → 读取文件并记录前后文件元信息
  → 严格校验 UTF-8
  → 创建新的 Document generation
  → 后台解析完整新 generation
  → 新 generation 可用后原子切换
  → 按最近块或最近标题恢复阅读锚点
```

重载期间继续显示旧 generation。任何一步失败都保留旧内容，并显示失败原因。文件在读取期间再次变化时，放弃本次结果并重新等待稳定。

## 11. Markdown 解析

### 11.1 解析选项

md4c 至少启用：

- UTF-8 输入。
- GFM 表格。
- 任务列表。
- 删除线。
- 所需的基础扩展。

不开启或自行执行原始 HTML 和任意脚本。原始 HTML 在当前阅读器中作为普通文本或源码块显示。

### 11.2 流式块构建

解析在后台线程执行，回调产生的事件交给 `StreamingBlockBuilder`：

```text
文件字节
  → md4c 回调
  → 构建完成的不可变 Block
  → 按批次发送到 UI
  → UI 追加到当前 generation
  → 可见部分立即布局和绘制
  → 后台继续解析
```

批次满足以下任一条件时发送：

- 约 16 ms 已积累新内容。
- 已积累约 64 个完整块。
- 当前开放块超过 32 KiB 且到达安全文本边界。

超长段落、列表项或代码块不能等待块闭合后才进入首屏。开放块达到阈值时拆为连续片段：

- 每段拥有独立 BlockId，但共享语义块 ID。
- 片段之间不增加段落间距。
- 行内样式可在片段边界安全拆分。
- 复制时按语义块还原文本，不把内部片段边界当作换行。

解析回调返回非零值以支持取消。UI 只接收与当前 `DocumentId + generation` 匹配的批次，过期批次直接丢弃。

当前实现采用“前缀首屏 + 完整后台解析 + 后处理分片”：完整 md4c 解析结束后，超过 12 KiB 的 Text Block 拆成连续显示片段；超过 64 个数据行的 Table Block 拆成多个连续表格块。复制通过 `continuesPreviousBlock` 区分同一段落片段，不插入合成换行。详细记录见 [15-超大单块虚拟化.md](./15-超大单块虚拟化.md)。

### 11.3 解析状态

```text
Idle → Reading → Parsing → Partial → Complete
                         ↘ Failed
```

- `Partial` 表示首屏或部分块已经可用。
- `Complete` 表示全文解析成功。
- `Failed` 可以保留 Partial 内容。
- 关闭 Tab 或重载产生新 generation 时，旧任务进入 Cancelled。

## 12. 文档模型

### 12.1 文档

`OpenDocument` 是 UI 线程拥有的可追加容器：

- 文档路径和显示标题。
- 当前 generation。
- 原始 UTF-8 文本。
- 顺序块列表。
- 解析状态。
- 文档级缓存代次。

Block 一旦发布不可修改。解析期间只能向文档尾部追加新块，不能在后台原地修改 UI 已引用的块。

### 12.2 Block

```cpp
enum class BlockKind {
  Text,
  Table,
  Image,
  Flowchart,
  Rule
};

class Block {
public:
  virtual ~Block() = default;
  virtual BlockId id() const = 0;
  virtual std::uint64_t semanticId() const = 0;
  virtual BlockKind kind() const = 0;
};
```

Block 不提供会修改内容的 `layout()`。布局由 LayoutEngine 根据 Block 内容和条件生成独立结果。

### 12.3 TextBlock

TextBlock 保存：

- 语义类型：段落、标题级别、列表项、引用、代码块。
- 嵌套层级、列表缩进和列表标记。
- 有序列表起始序号。
- 有序 `InlineSpan` 列表。
- 块内规范化 UTF-8 文本及行内范围。

InlineSpan 至少支持普通、粗体、斜体、删除线、行内代码和链接，并保存目标地址与该 Span 在块内规范化文本中的字节范围。

#### 列表排版

- 一级列表标记槽左边缘位于普通正文内容左边界 `L + 4 DIP`，不得突出到正文左侧。
- 无序列表文本位于标记槽之后，一级槽宽为 28 DIP。
- 有序列表数字在标记槽内右对齐；数字位数增加时槽宽自动扩展。
- 嵌套列表每增加一级缩进 22 DIP。
- 列表续行和后续段落与列表正文左边缘对齐。
- 高度预估和实际文字布局共用同一套列表缩进计算，包含字体缩放。

### 12.4 TextPosition

文本位置不能使用屏幕坐标。统一定义为：

```text
TextPosition {
  blockId,
  utf8ByteOffset
}
```

这里的偏移量是块内规范化文本的 UTF-8 字节偏移，不声明为原始 Markdown 文件偏移；md4c 回调不保证提供可直接使用的源文件位置。所有文本位置必须落在 UTF-8 字符边界上，UTF-8 字节偏移不得直接当作 UTF-16 或字形索引使用，平台文本层负责转换。

## 13. 文本布局与绘制

### 13.1 平台接口

```cpp
struct TextStyle {
  FontRole role;
  float pointSize;
  bool bold;
  bool italic;
  bool monospace;
};

class TextEngine {
public:
  virtual ~TextEngine() = default;
  virtual TextMetrics measure(
      const TextStyle&, std::string_view utf8) = 0;
  virtual LineLayout layoutParagraph(
      const ParagraphRequest&) = 0;
};

class Painter {
public:
  virtual ~Painter() = default;
  virtual void setClip(const RectF&) = 0;
  virtual void drawTextLayout(const LineLayout&, const PointF&) = 0;
  virtual void drawRect(const RectF&, const PaintStyle&) = 0;
  virtual void drawLine(const PointF&, const PointF&, const PaintStyle&) = 0;
  virtual void drawImage(const ImageHandle&, const RectF&) = 0;
};
```

`TextEngine` 和 `Painter` 的 wxWidgets 实现位于平台层。首版只在 UI 主线程调用字体度量和绘制，避免跨线程共享 `wxDC`。

### 13.2 字体

- 正文默认字体候选为 `Microsoft YaHei UI`、`Segoe UI` 和系统 sans-serif。
- 代码默认字体候选为 `Cascadia Mono`、`Consolas` 和系统 monospace。
- 如果首选字体不存在，按候选顺序回退。
- 字体、字号和 DPI 是布局缓存键的一部分。
- 首版不提供字体设置界面；外观模式通过“查看 > 外观”选择，不提供自定义配色或主题市场。

### 13.3 排版规则

- Latin 文本优先在空格和合法断词点换行。
- CJK 文本按字符边界换行，并处理常见标点禁则。
- 超长不可断 URL 或标识符在必要时硬断。
- 制表符按 4 个空格宽度展开。
- 代码块在可用宽度内软换行，复制时保留原始换行。
- 表格超宽时在表格块内部横向滚动，不产生整篇文档的横向滚动。

### 13.4 行布局

`LineLayout` 保存：

- 每行的文档坐标。
- 每行的 UTF-8 字节范围。
- 行内样式 run。
- 基线和字形范围。
- 链接点击区域。

这些信息同时用于绘制、选择、复制和链接命中，避免布局后再单独猜测坐标。

## 14. 块布局与滚动

### 14.1 LayoutContext

```text
LayoutContext {
  contentWidth,
  dpiScale,
  fontConfiguration,
  paragraphSpacing,
  codeTabWidth
}
```

窗口宽度、DPI、字体或排版参数变化时，当前文档布局全部失效。

### 14.2 布局结果

LayoutEngine 为每个 Block 生成独立结果：

```text
BlockLayout {
  blockId,
  estimatedHeight,
  finalHeight,
  heightIsFinal,
  layoutVersion,
  optional line/table/image/flow data
}
```

布局结果存入 LayoutCache，不写入不可变 Block。

### 14.3 视口布局

- 首次显示只布局当前视口和前后约 1 屏 overscan。
- 滚动进入新区域时，按块补齐布局。
- 重内容先用估算高度占位，异步结果返回后替换。
- 单帧绘制只处理与视口相交的块。
- 采用 `wxAutoBufferedPaintDC` 或等价后备缓冲减少闪烁。

### 14.4 高度索引

使用 Fenwick tree 保存每个块的累计高度：

- `blockId → estimated/final height` 更新为 `O(log n)`。
- `scrollY → 可见块` 查询为 `O(log n)`。
- 块布局修正后同步更新总高度。
- 当前阅读锚点使用 `blockId + intraBlockY`，不仅保存像素偏移。

当锚点上方块高度变化时，调整滚动偏移，使锚点保持在屏幕上的相对位置。

## 15. 选择与复制

P0 不实现鼠标选择，但模型和行布局从 P0 开始必须保留文本范围信息。

P1 选择模型：

- 起点和终点均为 TextPosition。
- 支持同一块内和跨块选择。
- 拖到视口边缘时自动滚动。
- 复制结果为纯文本，不生成 HTML 或富文本。
- 段落之间插入换行，代码块内部保留原始换行。
- 表格按行优先、单元格之间用制表符分隔。
- TextBlock 已被卸载到缓存外时，选择需要能按需加载对应布局。

P1 不实现局部富文本复制，也不允许选择块结构本身。

当前实现使用 `blockIndex + utf8Offset` 作为选择点，支持向左或向右跨块拖选、拖到视口边缘自动滚动、`Ctrl+A`、`Ctrl+C` 和“编辑”菜单。剪贴板只写入 `wxTextDataObject` 纯文本；单元测试覆盖 UTF-8 边界、跨块拼接和表格文本，UI 回归覆盖真实拖选与系统剪贴板。

## 16. 表格

### 16.1 支持范围

- GFM 基础表格。
- 任意行列数量，但受文件大小和内存保护限制。
- 单元格内支持基础行内样式。
- 不支持 rowspan、colspan、嵌套表格和表格内代码块。

### 16.2 列宽

1. 测量每个单元格的最小不可断宽度和自然宽度。
2. 自然宽度最多按 32 em 估算，避免超长文本撑宽表格。
3. 在视口宽度内按最小宽度和自然宽度比例分配。
4. 所有列都达到最小宽度后仍超宽时，TableBlock 使用本地横向滚动。
5. 行高取该行所有单元格换行后的最大高度。

### 16.3 布局与绘制

- 表格布局结果进入 LayoutCache。
- 单元格文本使用与正文相同的 TextEngine。
- 表格横向滚动偏移属于 TableBlock 的交互状态，不改变文档总宽度。
- 复制时按视觉行顺序输出纯文本。

## 17. 图片

### 17.1 路径与格式

- 相对路径以当前 Markdown 文件所在目录为基准。
- 支持绝对路径、相对路径和 HTTP/HTTPS 网络 URL。
- 网络图片通过 Windows WinHTTP 异步下载，只允许 HTTP/HTTPS。
- 网络图片下载上限为 64 MiB，解码像素上限为 6400 万。
- P1 保证支持 PNG、JPEG、BMP 和 GIF 首帧。
- 其他格式可以尝试由平台解码器处理，但不作为验收保证。

### 17.2 加载

- 先显示基于 alt 文本或默认尺寸的占位。
- 网络图片在后台线程下载到内存，再交给 wxImage 解码。
- 下载和解码完成后更新图片尺寸和文档高度。
- 图片按内容宽度等比缩放，不放大超过原始尺寸。
- 解码失败显示稳定错误占位。
- 设置合理的像素总量上限，防止异常图片耗尽内存。
- 网络失败、超时或图片格式无效时显示稳定错误占位。
- 图片解码结果和缩放结果按绝对路径或 URL 缓存。

## 18. Flowchart

### 18.1 选择自研布局的原因

Graphviz 能覆盖完整 graph 能力，但当前需求只需要基础 flowchart。引入 libgvc 会增加：

- 运行时库和传递依赖。
- MinGW-w64 编译与二进制分发难度。
- 全局状态和线程安全风险。
- 对 <10 MB 发布包体的直接压力。

因此不引入 Graphviz，改用覆盖白名单语法的确定性分层 DAG 布局。对于超出能力的输入，按需求降级显示源码。

### 18.2 支持语法

支持：

- `flowchart` 或 `graph`。
- 方向 `TD`、`TB`、`BT`、`LR`、`RL`。
- 节点：矩形 `[]`、圆角 `()`、菱形 `{}`、圆形 `(())`。
- 边：`---`、`-->`、`-.->`、`==>`。
- 边标签：`A -->|label| B`。
- 链式声明：`A --> B --> C`。
- 单层 `subgraph ... end` 视觉分组。

不支持：

- 嵌套 subgraph。
- classDef、class、style、linkStyle、click。
- HTML 标签节点和图标节点。
- 多向边、双向箭头和复杂端口。
- 非 flowchart Mermaid 图类型。

任何不满足白名单的 flowchart 整体降级为原始代码块，不输出可能错误的半成品图。

### 18.3 布局

1. 解析为节点、边、边标签和单层 cluster。
2. 检测并临时断开来打破环。
3. 使用最长路径算法分层。
4. 以源声明顺序作为初始层内顺序。
5. 做一轮相邻层重心排序，减少明显交叉。
6. 用 TextEngine 测量节点标签并计算节点尺寸。
7. 根据主方向排布节点，最后绘制 cluster 边界。
8. 边使用直线或简单折线，箭头指向目标节点边界。

布局结果按 generation、源码哈希、字体、DPI 和内容宽度缓存。对于包含子图的图，首版只处理 cluster 内部节点，不保证跨 cluster 边的复杂避障。

### 18.4 异步策略

- 首屏先显示固定占位高度。
- 后台解析 flowchart 源码和建立图结构。
- UI 线程使用 TextEngine 完成文字度量和最终布局。
- 结果返回后替换占位并修正文档高度。
- 解析或布局失败时显示原始代码块。

## 19. 链接与 Shell

P1 外部链接仅允许：

- `http`
- `https`
- `mailto`

点击时通过系统 Shell 打开。未识别的协议、可执行文件路径和相对文件链接不自动打开。链接命中区域来自 LineLayout，不使用全文正则重新搜索。

内部锚点跳转属于 P2，现已实现：

- 根据文档标题建立唯一 heading slug 索引。
- slug 使用标题规范化文本生成：转小写、空格转连字符、移除常规标点、保留中文；同名标题追加 `-1`、`-2` 等后缀。
- 支持点击 `#heading` 跳转到对应标题。
- 支持百分号编码的 UTF-8 锚点。
- 目录具有“未打开、已展开、已收起”三种状态。
- 初始未打开时不显示目录栏；通过“查看 > 目录”打开为展开状态。
- 展开时使用固定 260 DIP 宽度并压缩正文；点击分隔线中部三角收起为约 24 DIP 的窄条。
- 收起状态点击右向三角重新展开；再次取消“查看 > 目录”后完全隐藏。
- 点击目录项复用同一标题跳转逻辑。
- 目录正文列表不常驻，但收起后保留窄条和展开三角。相对 Markdown 文档跳转仍未纳入当前版本。
- 不解析原始 HTML 自定义锚点；该能力不在 P2 范围。

当前已实现文内 `#heading` 点击跳转、确定性 slug 和固定宽度可折叠目录侧栏。

## 20. 缓存与内存

### 20.1 开放 Tab 不是文档 LRU

Tab 表示用户明确打开的工作集，不能因为“最近没用”而静默关闭。所有 Tab 都保留路径和阅读锚点；活动 Tab 永远不卸载。

内存软预算为 128 MiB，仅用于稳定性保护，不作为需求验收指标。超过预算时按以下顺序释放：

1. 清理非活动 Tab 的位图、流程图和图片中间结果。
2. 清理非活动 Tab 的 LayoutCache。
3. 内核仍超预算时，卸载非活动 Tab 的块模型和源文本，但保留 Tab 和阅读锚点；切回时重新读取和解析。

活动 Tab 不因软预算被卸载。

### 20.2 LayoutCache

缓存键至少包含：

```text
documentId + generation + blockId + contentWidth
+ dpiScale + fontConfiguration + layoutVersion
```

内容只追加不修改，因此缓存不需要按块内容做复杂失效。重新加载会提升 generation，从根上隔离旧结果。

### 20.3 其他缓存

- TextMetrics 缓存按字体、字号、DPI 和文本片段建立，设置节点数量上限。
- ImageCache 按 generation、规范路径、目标和 DPI 缓存。
- FlowchartCache 按 generation、源码哈希、宽度、字体和 DPI 缓存。
- 不建立跨应用的磁盘解析缓存。
- 不建立整屏或多文档视口位图缓存。

## 21. 并发模型

| 执行位置 | 职责 |
|---|---|
| UI 主线程 | 窗口、Tab、wx 事件、TextEngine、布局、绘制、剪贴板 |
| ParsePool | 文件解析和流式块构建，固定 2 个工作线程 |
| ImagePool | 图片读取和解码，固定 2 个工作线程 |
| FlowchartPool | flowchart 语法解析和图结构构建，固定 1 个工作线程 |
| Watcher | 系统文件变化通知，事件投递到 UI |
| IpcServer | 接收次实例路径，投递到 UI |

### 21.1 任务优先级

- 活动 Tab 的首批解析优先于非活动 Tab。
- 非活动 Tab 可以先完成文件读取和首批解析，再降速继续。
- 所有任务带 `TabId + DocumentId + generation + BlockId`。
- UI 收到结果时检查 generation 和 Tab 是否仍存在，不匹配则丢弃。
- 关闭 Tab 后取消未开始任务，正在执行的解析通过回调主动中止。

### 21.2 线程边界

- 后台线程不创建、不持有、不调用 wxWidgets UI 对象。
- 后台只交付值对象或不可变对象。
- `std::shared_ptr<const Block>` 可以跨线程传递。
- 布局结果和 TextPosition 转换在主线程完成。

## 22. UI 结构

主窗口组成：

```text
┌──────────────────────────────────────────────┐
│ 原生菜单：文件 | 查看 | 帮助                 │
├──────────────────────────────────────────────┤
│ TabStrip：文档 A | 文档 B | 文档 C           │
├──────────────────────────────────────────────┤
│ 非模态提示条（仅需要时显示）                 │
├──────────────────────────────────────────────┤
│ DocumentView                                 │
│ Markdown 内容 / 必要滚动条                   │
└──────────────────────────────────────────────┘
```

文件菜单至少包含：

- 打开文件。
- 重新加载当前文档。
- 退出。

查看菜单包含：

- 查找。
- 外观：跟随系统、浅色、深色。
- 目录。

帮助菜单包含：

- 使用说明，快捷键 `F1`。
- 关于 liteMark，显示应用版本、构建类型和 wxWidgets 版本。

不增加常驻工具栏或状态栏。查找栏只在查找期间出现。提示条只在文件变化、解析失败等状态出现。

为保持菜单精简，界面不显示“编辑”菜单、文件菜单中的“关闭当前 Tab”、查看菜单中的“上一个/下一个 Tab”。`Ctrl+C`、`Ctrl+A`、`Ctrl+W`、`Ctrl+Tab` 和 `Ctrl+Shift+Tab` 仍通过不可见加速键保持可用。

### 22.1 窗口行为

- 标准可移动、可缩放、可最小化窗口。
- 支持放置在第二屏。
- 启用 Per-Monitor V2 DPI 感知。
- 关闭最后一个 Tab 时关闭主窗口。
- 应用重启后按工作区状态恢复旧 Tab。

### 22.2 P2 目录侧栏

- “查看 > 目录”负责从隐藏状态打开目录；三角按钮负责展开和收起。
- 菜单勾选表示目录处于展开或收起状态，取消勾选会完全隐藏。
- 目录侧栏停靠在正文左侧，展开宽度固定为 260 DIP，不随窗口宽度按比例增长。
- 展开时正文使用剩余宽度重新排版；收起后只保留约 24 DIP 的窄条。
- 三角绘制在分隔线垂直中部；展开状态显示左向三角，收起状态显示右向三角。
- 打开或关闭侧栏时保留当前阅读块和块内相对位置，避免正文重排导致跳读。
- 菜单勾选状态与三角展开状态保持同步。
- 侧栏显示当前文档 H1–H6 标题及层级缩进。
- 点击目录项只跳转到对应标题，侧栏保持打开，方便连续跳转。
- 切换 Tab 时目录内容切换到目标文档，侧栏显示状态保持不变。
- 三态目录状态随工作区持久化，并在下次启动时恢复；旧版 `outline.visible=0/1` 自动迁移为隐藏/展开。
- 目录列表使用只绘制可见行的虚拟列表，不创建逐标题子窗口。
- 目录滚轮量按高精度事件累计，每档移动 3 行，并阻止事件穿透到正文。

### 22.3 文档内查找

- `Ctrl+F` 或“查看 > 查找”打开临时查找栏。
- 输入后约 140 ms 防抖，在后台搜索当前文档，不阻塞界面。
- ASCII 匹配不区分大小写，中文按 UTF-8 原文匹配。
- 全部匹配使用浅色高亮，当前匹配使用更明显的活动高亮。
- `Enter`/`F3` 下一个，`Shift+Enter`/`Shift+F3` 上一个，`Esc` 或关闭按钮隐藏。
- 切换 Tab 或文档解析完成后，使用当前查询重新搜索。
- 单个查询最多保留 10000 个结果，超出时显示“已截断”。
- 查找栏关闭后清除高亮，不保留常驻搜索 UI。

### 22.4 浅色与暗色模式

#### 模式

应用支持三个选项：

| 模式 | 行为 |
|---|---|
| 跟随系统 | 首次启动默认值；Windows 应用主题变化时即时跟随 |
| 浅色 | 忽略系统暗色设置，始终使用浅色主题 |
| 深色 | 忽略系统浅色设置，始终使用暗色主题 |

入口位于“查看 > 外观”，使用单选菜单项显示当前模式。选择后立即重绘所有已打开 Tab，不要求重启。主题偏好单独持久保存；窗口位置、Tab 和滚动状态由独立的 P2 工作区状态模块恢复。

主题偏好只保存 `system`、`light`、`dark` 三个值之一，写入用户配置目录；读取失败或值非法时回退到跟随系统。该设置与 P2 的会话恢复相互独立。

#### 颜色令牌

| 语义 | 浅色 | 深色 |
|---|---|---|
| 窗口背景 | `#F7F8FA` | `#202124` |
| 文档背景 | `#FFFFFF` | `#1E1E1E` |
| 正文 | `#24292F` | `#D4D4D4` |
| 次要文字 | `#57606A` | `#9AA0A6` |
| 链接 | `#0969DA` | `#66B2FF` |
| 边框 | `#D0D7DE` | `#3C4043` |
| 代码块背景 | `#F6F8FA` | `#252526` |
| 引用边线 | `#D0D7DE` | `#5F6368` |
| 文本选择背景 | `#B6D7FF` | `#264F78` |
| 焦点和强调 | `#0969DA` | `#66B2FF` |

正文、链接和交互元素的关键文字与背景对比度至少满足 WCAG AA 的普通文本要求。主题值集中定义为语义令牌，Block 和 LayoutEngine 不直接保存颜色。

#### 覆盖范围

- 文档正文、标题、列表、引用、代码块、表格边框和单元格背景。
- Tab、菜单选中态、滚动条区域、提示条和文本选择高亮。
- Flowchart 节点背景、边框、文字和连线。
- 图片保留自身颜色，不应用反色滤镜。
- 手动选择深色时，平台层应请求 Windows 支持的深色标题栏和原生控件主题；操作系统不支持的部分仍保证自定义内容区一致，不残留大面积纯白控件。

主题切换不需要重新排版，也不使 LayoutCache 失效。ThemeController 更新颜色令牌并通过平台层请求窗口重绘；需要平台重新绘制的控件通过 wxWidgets 3.3 的主题接口刷新。

## 23. 性能设计

### 23.1 P0 热打开测量

基准输入：100 KB–200 KB Markdown，包含中英文、标题、段落、列表、代码块和长段落。

验收机器：用户的 AMD 8845 本机。每次测试记录系统版本、内存容量、SSD、电源模式、显示分辨率和缩放比例。

计时起点：

- 从文件菜单打开：用户在文件对话框确认文件后。
- 从资源管理器或第二实例打开：主实例收到 IPC 路径后。

计时终点：首个可见区域完成绘制，用户能够辨认正文文字。

验收口径：

- 应用已启动并空闲。
- Release 构建，不附加调试器。
- 同一测试文件在 20 次独立打开中统计 P95。
- P95 不超过 300 ms。

如果相同文件已在 Tab 中打开，只执行 Tab 激活，不属于热打开测量。

### 23.2 10 MB 挑战项

- 从进程启动开始，到首个可见区域完成绘制。
- 只记录数据，不作为 P0 或 P1 通过条件。
- 可以按占位方式显示后续内容。

### 23.3 关键优化

- 首批解析批次到达后立即布局首屏。
- 首屏仅布局可见区和前后约 1 屏。
- 文本度量缓存覆盖重复字体和样式。
- 不等待全文解析、图片或 flowchart。
- 布局与绘制都只处理可见块。
- 背景 Tab 解析降低频率，避免抢占活动 Tab。

### 23.4 P1 性能指标

- **普通首屏**：100 KB–200 KB 文档冷启动，从启动程序或接收文件路径开始，到首个可读视口完成绘制，P95 不超过 500 ms。
- **Tab 切换**：已打开 Tab 之间切换，从操作开始到目标完整帧出现，P95 不超过 50 ms；不出现空白中间帧，滚动位置保持。
- **滚动**：大文档连续滚动，P95 单帧不超过 16.7 ms，测试期间无超过 50 ms 的单帧。
- 图片和 flowchart 占位到完成的时间只记录，不纳入当前强制阈值。
- 长时间打开、关闭和切换后的稳定性作为 P1 必须通过的场景。

以上指标统一在 AMD 8845 本机、Release 构建、固定电源模式和固定显示缩放下测量。

### 23.5 性能测试自动化

性能测试由 `scripts/benchmark.ps1` 执行，固定生成 20 份约 150 KB 文档和 5 份 10 MB 文档。脚本覆盖冷启动、热打开、Tab 切换和滚动，并把原始事件和 P50/P95/Max 写入 `build` 目录。

冷启动、热打开和 Tab 切换均在首个可读视口完成应用侧绘制时结束计时。2026-10-22 的本机结果和完整环境记录见 [06-P1性能测试记录.md](./06-P1性能测试记录.md)。

## 24. 发布与包体

### 24.1 发布形式

- 首版主发布物是 Windows x64 安装器。
- 安装器负责安装程序、创建卸载项和注册 `.md`/`.markdown` 文件关联。
- 开始菜单快捷方式始终创建。
- 桌面快捷方式作为默认勾选的可选项。
- Markdown 文件关联作为默认勾选的可选项；取消或卸载时恢复原关联。
- 完成页保留“运行 liteMark”复选框，但默认不勾选。
- 如果后续同时发布便携包，便携包也受 <10 MB 限制。
- 不引入自动更新服务。

### 24.2 依赖和体积

- 不打包 Chromium、WebView、Graphviz、Cairo。
- wxWidgets、md4c 和必要运行库随安装器一起分发。
- MinGW 运行时采用静态链接或随包部署，确保用户机器无需另装编译器运行库。
- Release 构建去除调试符号，PDB、源码、测试资料和示例文档不计入发布包体。
- 不使用 UPX 等压缩壳，避免病毒误报和启动开销。
- 在构建流水线中直接检查最终安装器字节数，小于 10 MB 才算通过。

### 24.3 许可

发布包必须包含所用第三方库的许可证文本。文件关联、图标和卸载行为使用安装器标准机制。

当前已经落地的 CTest 入口、需求覆盖和待补测试见 [07-单元测试矩阵.md](./07-单元测试矩阵.md)。未实现功能不通过空测试伪装覆盖。

### 25.2 集成测试

### 25.3 视觉测试

### 25.4 性能与稳定性

- 热打开 100 KB–200 KB 文档 20 次，记录 P50/P95。
- 10 MB 冷启动挑战时间线。
- P1 Tab 切换和滚动帧耗时。
- 长文档连续滚动 10 分钟。
- 反复打开、关闭和切换 1 小时。
- 文件持续写入时反复发送变化事件。

## 27. 已验证的边界与剩余事项

### 27.1 已确定

- 同窗 Tab，不做分栏。
- 单实例单窗口，同文件复用 Tab。
- 文件变化确认后重载，自动重载不做。
- P0/P1 功能边界。
- 核心数据模型、线程边界和缓存方式。
- P1 复制为跨块纯文本。
- P1 提供跟随系统、浅色和暗色三种模式，并保存手动选择。
- 本地图片格式和 flowchart 白名单。
- 表格列宽策略和超宽处理。
- 安装器形式及 <10 MB 包体检查。
- 不再使用 Graphviz、Cairo 和整屏位图缓存。

### 27.2 仅剩需求层待细化

以下事项不是设计未决项，也不阻塞 P0：

- flowchart 白名单的边界测试样例集。

P1 性能测试的固定样本、自动化脚本和首轮结果已经记录在 [06-P1性能测试记录.md](./06-P1性能测试记录.md)。

### 27.3 P2 范围

- 文档内部锚点跳转和固定宽度可折叠目录侧栏。（已实现）
- 通过“查看 > 目录”勾选时常驻并重排正文，取消时隐藏；目录项可跳转到标题。（已实现）
- 最近文档记录，最多 5 条。（已实现）
- 窗口位置、Tab 顺序、当前 Tab 和各文档滚动位置恢复。（已实现）

工作区状态写入用户配置目录下的 `liteMark/workspace.ini`。测试可通过 `LITEMARK_CONFIG_DIR` 指向隔离目录，避免恢复用户真实 Tab 或污染最近文档。启动时只恢复仍存在的文件；关闭窗口时保存窗口位置、最大化状态、目录三态、Tab 路径、顺序、当前 Tab 和滚动位置。

## 28. 变更规则

- 任何扩大 Tab、文件监听、解析、布局、异步或发布依赖的改动，必须先更新本文档。
- 改变 Block、generation 或 TextPosition 语义属于架构变更，需要评审缓存、选择、重载和异步任务。
- 重新引入浏览器内核、Graphviz、Cairo、整屏位图缓存或自动重载，必须说明对包体、首屏和内存的影响。
- 性能结论必须附测试文件、硬件环境、构建模式和统计口径。
- 需求变化先更新 [02-需求文档.md](./02-需求文档.md)，再更新本设计。
