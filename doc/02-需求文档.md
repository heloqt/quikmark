## 1. 产品定位

liteMark 是一个面向开发者的原生、轻量、只读 Markdown 阅读面板。它不替代编辑器，而是作为常驻第二屏的参考窗口，用于频繁查阅需求、设计和 AI 生成的 Markdown 文档。

产品必须同时守住两条并列硬目标：

1. **干净阅读**：界面以文档为唯一主体，不引入编辑器和浏览器式噪声。
2. **快**：冷启动、文档切换和长文档滚动都要达到明确性能指标。

两条目标缺一不可。“干净”决定了用户为什么选择它，“快”决定了用户能否长期将它留在屏幕上。

## 2. 用户与核心场景

### 2.1 目标用户

- 使用双屏或宽屏的软件开发者。
- 经常阅读几十 KB 到 200 KB 的 AI 生成需求、设计和技术文档。
- 偶尔需要打开 1 MB 到 10 MB 的大文档。
- 主屏编写代码或与 AI 对话，副屏持续查看 Markdown 文档。

### 2.2 核心场景

| 编号 | 场景 | 期望结果 |
|---|---|---|
| SC-001 | 主屏写代码，副屏阅读文档 | 阅读器独立常驻，不抢占、不依附编辑器 |
| SC-002 | 通过文件菜单、资源管理器或拖入打开文档 | 文档在现有窗口的新 Tab 中打开 |
| SC-003 | 同时打开 3–5 份中小型文档 | 通过 Tab 切换，各文档保留滚动位置 |
| SC-004 | 打开 1–10 MB 大文档 | 可阅读、可滚动；300 ms 仅为挑战目标 |
| SC-005 | 阅读包含表格和 Mermaid flowchart 的文档 | 完成版能正确显示；复杂内容加载期间不得阻塞首屏 |
| SC-006 | 已打开文件被外部程序修改 | 阅读器检测到变化，并按确认后的重载规则处理 |
| SC-007 | 应用已运行时再次双击或拖入文件 | 不产生第二个主窗口，文件进入已有窗口 |

## 3. 产品目标与边界

### 3.1 必须达成的目标

| 编号 | 目标 |
|---|---|
| OBJ-001 | 提供独立、纯净、只读的 Markdown 文档视图 |
| OBJ-002 | 在同一窗口通过 Tab 打开多份文档并切换 |
| OBJ-003 | P0 热打开达到 300 ms；其余性能指标在 P1 明确并验收 |
| OBJ-004 | 不依赖 Electron、Chromium 或其他浏览器内核 |
| OBJ-005 | 核心逻辑保持平台可移植，当前以 Windows 10/11 为验收平台 |
| OBJ-006 | 支持完成版所需的表格、图片和 Mermaid flowchart 基础显示 |
| OBJ-007 | 一个进程、一个主窗口，重复启动时复用已有窗口 |
| OBJ-008 | 支持与系统一致的浅色和暗色阅读体验 |

### 3.2 明确不做

| 编号 | 非目标 |
|---|---|
| NG-001 | 不实现编辑能力，包括修改、撤销和粘贴图片；P1 的只读选择和复制不属于编辑能力 |
| NG-002 | 不实现完整 GFM 或完整 Mermaid 支持 |
| NG-003 | 不实现公式和复杂 Mermaid 渲染；无法渲染时降级为原始代码展示 |
| NG-004 | 不实现插件、主题市场、云同步、双链、知识图谱 |
| NG-005 | 不加入为丰富界面而存在的工具栏或状态栏；文件菜单、文档 Tab 和 P2 可收回目录侧栏属于必要入口 |
| NG-006 | 不以商业化和竞品对比为目标 |
| NG-007 | 不实现同一窗口内的左右或上下分栏阅读 |

### 3.3 已补充的边界

- 非法 UTF-8、超过 64 MiB 的文件和损坏内容显示明确错误；解析中途失败可保留已显示内容。
- `http`、`https`、`mailto` 外链在 P1 使用系统默认应用打开。
- 文内 `#heading` 锚点和可收回目录侧栏归入 P2。
- 关闭最后一个 Tab 时关闭窗口。
- 最近文档、窗口位置、Tab 和滚动状态恢复归入 P2。
- 主发布形式为安装器；不提供自动更新。

| FR-005 | 长文档滚动 | 可连续滚动；未布局内容可按需出现；滚动条不因布局修正而剧烈跳动 |
| FR-006 | Tab 页多文档 | 同一窗口内使用一个文档对应一个 Tab 的形式维护多份已打开文档 |

## 7. 非功能需求

### 7.1 性能

| 编号 | 阶段 | 指标 | 目标 |
|---|---|---|---|
| NFR-PERF-001 | P0 | 应用已运行时热打开 100 KB–200 KB 文档 | 不超过 300 ms |
| NFR-PERF-002 | P0 挑战目标 | 10 MB 文档从进程启动到首屏可读 | 300 ms；不作为验收门槛 |
| NFR-PERF-101 | P1 | 100 KB–200 KB 文档冷启动首屏可读 | P95 不超过 500 ms |
| NFR-PERF-102 | P1 | 已打开文档 Tab 切换 | P95 不超过 50 ms，无空白中间帧，保留滚动位置 |
| NFR-PERF-103 | P1 | 大文档连续滚动 | P95 单帧不超过 16.7 ms；测试期间无单帧超过 50 ms |
| NFR-PERF-104 | P1 | 重内容加载 | 表格、图片、flowchart 可晚于首屏完成，但必须稳定占位 |

**热打开定义**：应用已经运行时，从用户确认打开文件或运行中的实例收到外部文件路径开始，到首个可见区域出现可辨认文档文本为止。不要求全文解析、全文布局、图片解码或 flowchart 布局已经完成。

**热打开基准**：以 100 KB–200 KB 的典型文档作为验收输入；10 MB 文档仍只属于挑战目标。

以上 P1 指标在用户的 AMD 8845 本机、Release 构建、固定电源模式和固定显示缩放下测量。热打开和 P1 冷启动首屏分开统计。

### 7.2 资源与稳定性

| 编号 | 指标 | 目标 |
|---|---|---|
| NFR-RES-001 | 主发布制品体积 | 小于 10 MB，且不含 Chromium；同时发布安装包和便携包时两者都受限 |
| NFR-RES-002 | 内存 | 暂不作为验收标准；仍需避免明确的内存泄漏和持续失控增长 |
| NFR-STAB-001 | 长时间使用 | P1 阶段细化反复打开、切换、滚动时的稳定性验收 |

10 MB 文档仍需具备打开和阅读能力，但内存峰值不进入当前验收门槛。发布包体按用户最终下载的主发布制品计量，不计调试符号、源码和测试资料。

### 7.3 可移植性

| 编号 | 指标 | 目标 |
|---|---|---|
| NFR-PORT-001 | 平台验收 | 当前只验收 Windows 10/11 |
| NFR-PORT-002 | 构建工具链 | Windows 使用 MinGW-w64（GCC） |
| NFR-PORT-003 | 架构边界 | 作为长期要求保留；核心逻辑与平台解耦，为 Linux/macOS 留出空间 |

架构可移植性当前只作为设计和代码约束保留，Linux/macOS 不进入本阶段验收。

## 8. 验收标准

### 8.1 干净线

| 验收项 | 通过条件 |
|---|---|
| 纯净阅读 | 打开后直接看到文档；没有编辑工具栏、源码切换或侧边栏；文件菜单和 Tab 不属于噪声 |
| 独立窗口 | 可以独立放置在第二屏，不依赖编辑器宿主 |
| 多文档 | 能在同一窗口打开多个 Tab 并切换，各 Tab 保留滚动位置 |
| 打开入口 | 文件菜单、资源管理器文件关联和拖入三种入口均可用 |
| 单实例 | 重复启动不产生第二个主窗口，携带的文件进入已有窗口 |
| 视觉噪声 | 除文档、Tab、文件菜单和必要滚动条外，没有多余常驻控件 |
| 主题 | P1 默认跟随系统；浅色和暗色下正文、代码块、表格、链接、选择、Tab 和滚动区域均保持可读 |

### 8.2 快线

| 验收项 | 通过条件 |
|---|---|
| P0 热打开 | 应用已运行时打开 100 KB–200 KB 文档，按 7.1 定义不超过 300 ms |
| P0 发布包体 | 用户最终下载的主发布制品小于 10 MB，且不含 Chromium；安装包和便携包同时存在时两者都受限 |
| P1 首屏 | 100 KB–200 KB 文档冷启动首屏 P95 不超过 500 ms |
| P1 Tab 切换 | 3–5 份文档来回切换 P95 不超过 50 ms，无空白中间帧 |
| 阅读状态 | 每份文档切换回来后恢复原滚动位置 |
| P1 滚动 | 大文档连续滚动 P95 单帧不超过 16.7 ms，无超过 50 ms 的单帧 |
| 挑战项 | 10 MB 文档从进程启动到首屏 300 ms 仅记录结果，不判定验收失败 |
| 内存 | 不设验收上限，但明显泄漏和持续失控增长仍需修复 |

**P0 通过条件**：P0 功能、干净线、热打开和发布包体通过。

**完成版通过条件**：P0 条件继续通过，P1 功能与 P1 性能指标通过。10 MB 冷启动挑战项不参与通过或失败判定。

## 10. 后续细化事项

当前 P0、P1、P2 的产品范围和验收口径已经确认。后续只细化测试样例和实现细节，不新增产品范围：
