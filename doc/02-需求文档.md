## 1. 产品定位

liteMark 是一个面向开发者的原生、轻量、只读 Markdown 阅读面板。它不替代编辑器，而是作为常驻第二屏的参考窗口，用于频繁查阅需求、设计和 AI 生成的 Markdown 文档。

产品必须同时守住两条并列硬目标：

1. **干净阅读**：界面以文档为唯一主体，不引入编辑器和浏览器式噪声。
2. **快**：冷启动、文档切换和长文档滚动都要达到明确性能指标。

两条目标缺一不可。“干净”决定了用户为什么选择它，“快”决定了用户能否长期将它留在屏幕上。

## 2. 用户与核心场景

### 2.1 目标用户

- 使用双屏或宽屏的软件开发者。
- 经常阅读几十 KB 到 200 KB 的 AI 生成需求、设计和技术文档。
- 偶尔需要打开 1 MB 到 10 MB 的大文档。
- 主屏编写代码或与 AI 对话，副屏持续查看 Markdown 文档。

### 2.2 核心场景

| 编号 | 场景 | 期望结果 |
|---|---|---|
| SC-001 | 主屏写代码，副屏阅读文档 | 阅读器独立常驻，不抢占、不依附编辑器 |
| SC-002 | 打开 100 KB–200 KB 文档 | 首屏在 100–200 ms 内可读 |
| SC-003 | 同时打开 3–5 份中小型文档 | 快速切换，无闪烁，各文档保留滚动位置 |
| SC-004 | 打开 1–10 MB 大文档 | 首屏不超过 300 ms，滚动流畅且不崩溃 |
| SC-005 | 阅读包含表格和 Mermaid flowchart 的文档 | 完成版能正确显示；复杂内容加载期间不得阻塞首屏 |

## 3. 产品目标与边界

### 3.1 必须达成的目标

| 编号 | 目标 |
|---|---|
| OBJ-001 | 提供独立、纯净、只读的 Markdown 文档视图 |
| OBJ-002 | 同时打开多份文档并快速切换 |
| OBJ-003 | 首屏、切换、滚动和内存占用达到本文档规定指标 |
| OBJ-004 | 不依赖 Electron、Chromium 或其他浏览器内核 |
| OBJ-005 | 核心逻辑保持平台可移植，当前以 Windows 10/11 为验收平台 |
| OBJ-006 | 支持完成版所需的表格、图片和 Mermaid flowchart 基础显示 |

### 3.2 明确不做

| 编号 | 非目标 |
|---|---|
| NG-001 | 不实现编辑能力，包括光标、编辑选区、撤销、粘贴图片 |
| NG-002 | 不实现完整 GFM 或完整 Mermaid 支持 |
| NG-003 | 不实现公式渲染；非 flowchart 类 Mermaid 在无法显示时可用图片占位或不显示 |
| NG-004 | 不实现插件、主题市场、云同步、双链、知识图谱 |
| NG-005 | 不加入为丰富界面而存在的工具栏、侧边栏或状态栏 |
| NG-006 | 不以商业化和竞品对比为目标 |

### 3.3 原文未覆盖但后续需要定义的边界

- 文件编码、换行符和异常文件的处理策略。
- 文件不存在、无权限、内容损坏等错误提示方式。
- 外链点击策略、相对路径解析和图片安全边界。
- 应用退出、窗口关闭、最近文档持久化等生命周期规则。
- 安装包格式、发布方式和升级机制。

这些内容不能视为已经确定的需求，应在下一轮细化时补齐。

## 4. 运行环境与约束

| 编号 | 约束 |
|---|---|
| ENV-001 | 主验收平台为 Windows 10/11。 |
| ENV-002 | 性能基准设备参考 Intel i3-12 代档位。 |
| ENV-003 | 使用 MinGW-w64（GCC）作为 Windows 构建工具链。 |
| ENV-004 | 架构保持可移植；Linux/macOS 当前不纳入验收。 |
| ENV-005 | 文档存储介质以 NVMe 或 SATA SSD 为基准，机械硬盘不作性能保证。 |
| ENV-006 | 安装包应力求轻量，不能包含 Chromium，目标准为十几 MB 量级。 |
| ENV-007 | 不内嵌浏览器、不执行 JavaScript。 |
| ENV-008 | 项目定位为个人练手项目，不是商业化产品。 |

## 5. 版本范围

| 范围 | 内容 | 说明 |
|---|---|---|
| 架构骨架 M0 | 工程、块模型、缓存接口、渲染抽象、空文档视图 | 用于尽早锁定关键抽象 |
| MVP | P0 能力、基础 Markdown 显示、多文档打开/切换、滚动位置保留 | 形成“干净、多文档流畅切换”的最小闭环 |
| 完成版 | MVP + 基础表格 + 图片 + Mermaid flowchart 基础显示 | 对应原文 P1 |
| 后续可选 | 代码高亮、搜索、合并单元格、更多 Mermaid 能力 | 不阻塞 MVP 和完成版验收 |

原文中“可按 P1 显示基础表格/图片”与“完成版才包含表格/flowchart”存在阶段性表达差异。本文档按实现阶段解释为：**MVP 保留块级占位；完成版提供基础显示能力。**

## 6. 功能需求

### 6.1 P0：MVP 必需

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-001 | 打开本地 Markdown 文件并显示 | 用户可选择文件，窗口显示对应内容 |
| FR-002 | 保持纯阅读态 | 独立窗口；无编辑工具栏、源码/预览切换、侧边栏 |
| FR-003 | 显示基础 Markdown | 标题、段落、粗体、斜体、列表、引用、代码块、链接、水平线；图片引用至少可解析并占位 |
| FR-004 | 首屏快速可读 | 不等待全文布局或重内容完成，即可显示首个可见区域 |
| FR-005 | 长文档滚动 | 可连续滚动；未布局内容可按需出现；滚动条不因布局修正而剧烈跳动 |
| FR-006 | 同时打开多份文档 | 用户可在同一应用内维护多个已打开文档 |
| FR-007 | 快速切换文档 | 切换时复用已解析和已布局结果，不重建整个视图 |
| FR-008 | 保留文档阅读状态 | 每份文档独立保存滚动位置；切回时恢复 |
| FR-009 | 基础链接行为 | 文档内链接可识别；点击外部链接的具体交互待细化 |
| FR-010 | 重内容占位 | 首屏尚未准备好的表格、图片、flowchart 不得阻塞基础文本显示 |

### 6.2 P1：完成版

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-101 | 显示基础表格 | 支持常用行列、简单列宽分配、单元格内换行 |
| FR-102 | 表格能力限制 | 首版不以合并单元格和复杂列宽为重点，可留待二期 |
| FR-103 | 显示本地及相对路径图片 | 图片异步解码；加载期间显示稳定占位；失败时有降级表现 |
| FR-104 | 显示 Mermaid flowchart 基础子集 | 至少覆盖节点、边、方向和基础子图；具体语法白名单待细化 |
| FR-105 | flowchart 异步布局 | 先显示占位，完成 Graphviz 布局后替换，不阻塞首屏阅读 |
| FR-106 | 缓存重内容结果 | 表格布局、图片解码和 flowchart 坐标可复用，切换后不重复计算 |

### 6.3 P2：后续可选

| 编号 | 需求 | 约束 |
|---|---|---|
| FR-201 | 代码块语法高亮 | 只允许轻量实现；若影响性能或包体，可不做 |
| FR-202 | 文档内搜索 | 不进入 MVP；实现时不得破坏纯净阅读态 |

### 6.4 暂不纳入

| 能力 | 处理方式 |
|---|---|
| 编辑、保存、撤销 | 不做 |
| 完整 GFM、完整 Mermaid | 不做 |
| 公式渲染 | 不做运行时渲染 |
| 非 flowchart 类 Mermaid | 图片占位或不显示 |
| 插件、主题市场、云同步、双链、图谱 | 不做 |

## 7. 非功能需求

### 7.1 性能

| 编号 | 指标 | 目标 |
|---|---|---|
| NFR-PERF-001 | 100 KB–200 KB 文档冷启动首屏可读 | 100–200 ms |
| NFR-PERF-002 | 1 MB–10 MB 文档冷启动首屏可读 | 不超过 300 ms |
| NFR-PERF-003 | 已打开文档切换 | 小于 50 ms，无闪烁，保留滚动位置 |
| NFR-PERF-004 | 大文档滚动 | 稳定流畅，目标 60 fps |
| NFR-PERF-005 | 重内容加载 | 表格、图片、flowchart 可晚于首屏完成，但必须稳定占位 |

**首屏可读定义**：从双击文档或向进程传入文件开始计时，到首个可见区域已经出现可辨认的文档文本为止。该指标不要求全文解析、全文布局、图片解码或 flowchart 布局已经全部完成。

**热打开定义待确认**：应用已经运行时再打开文档的耗时目标，原文未单独给出，后续需补充。

### 7.2 资源与稳定性

| 编号 | 指标 | 目标 |
|---|---|---|
| NFR-RES-001 | 安装包 | 不含 Chromium；目标准为十几 MB 量级 |
| NFR-RES-002 | 单文档内存 | 10 MB 文档可打开、可阅读 |
| NFR-RES-003 | 多文档内存 | 使用 LRU 等策略限制常驻文档和位图；内存不得持续失控增长 |
| NFR-STAB-001 | 长时间使用 | 反复打开、切换、滚动无崩溃、无明显内存泄漏 |

“10 MB 文档可接受”的具体内存上限尚未给出，需要在性能方案确定后量化。

### 7.3 可移植性

| 编号 | 指标 | 目标 |
|---|---|---|
| NFR-PORT-001 | 平台验收 | 当前只验收 Windows 10/11 |
| NFR-PORT-002 | 构建工具链 | Windows 使用 MinGW-w64（GCC） |
| NFR-PORT-003 | 架构边界 | 解析、布局、缓存、渲染抽象与平台解耦，为后续适配留出空间 |

## 8. 验收标准

### 8.1 干净线

| 验收项 | 通过条件 |
|---|---|
| 纯净阅读 | 打开后直接看到文档；没有编辑工具栏、源码切换或侧边栏 |
| 独立窗口 | 可以独立放置在第二屏，不依赖编辑器宿主 |
| 多文档 | 能打开多份文档并快速切换 |
| 视觉噪声 | 除文档和必要滚动条外，没有多余常驻控件 |

### 8.2 快线

| 验收项 | 通过条件 |
|---|---|
| 首屏 | 按 7.1 的定义和阈值测量 |
| 切换 | 3–5 份 100 KB–200 KB 文档来回切换小于 50 ms，无闪烁 |
| 阅读状态 | 每份文档切换回来后恢复原滚动位置 |
| 滚动 | 10 MB 文档滚动稳定，目标 60 fps |
| 内存 | LRU 生效，长时间操作后内存没有持续异常增长 |
| 包体 | 无 Chromium，安装包符合轻量目标 |

**最终达标条件：干净线与快线都通过。** 功能可用但界面噪声明显，或界面干净但性能不达标，均不能视为完成。

## 10. 待确认事项

以下问题会直接影响后续详细设计和验收，需要在进入实现细化前确认：

1. **并排与切换**：原文同时写了“多文档并排/快速切换”。“并排”是否指同一窗口内分栏？若 MVP 只要求快速切换，应明确并排属于后续范围。
2. **热打开指标**：应用已运行时打开新文档的首屏目标尚未定义。
3. **内存预算**：10 MB 单文档可接受的具体峰值内存、多文档总预算和常驻文档数量需要量化。
4. **文件处理**：UTF-8 之外是否支持其他编码；超大文件、空文件、损坏文件的预期行为。
5. **链接与图片**：外链用什么方式打开；相对路径以文档目录为准是否确认；支持哪些图片格式。
6. **flowchart 子集**：节点形状、连线类型、标签、方向、子图等支持边界需要列出白名单。
7. **表格边界**：基础表格是否首版只支持无合并单元格；超宽表格是横向滚动还是缩放。
8. **代码高亮与搜索**：是否进入首个可发布版本，还是明确留到二期。
9. **包体上限**：原文“十几 MB 量级”需要转换成验收上限。
10. **发布形态**：便携压缩包、安装器或两者同时提供。
