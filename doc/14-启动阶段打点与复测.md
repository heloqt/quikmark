# 启动阶段打点与复测

## 1. 结论

测试日期：2026-10-23

本轮完成三段改造：

1. 拆分 `file_read`、`utf8_convert`、`md4c_parse` 和后续处理耗时。
2. 移除 `bytes -> wxString -> UTF8 -> std::string` 的往返复制。
3. 大文件先解析最多 32 KB 的安全前缀并显示首屏，完整文档继续在后台解析。

最终结果为：

| 场景 | P50 | P95 | 最大值 |
|---|---:|---:|---:|
| 150 KB 冷启动首屏 | 284.701 ms | 314.635 ms | 317.041 ms |
| 10 MB 冷启动首屏 | 325.682 ms | 328.849 ms | 328.849 ms |
| 10 MB 热打开首屏 | 17.888 ms | 30.918 ms | 30.918 ms |

10 MB 冷启动从改造前的约 `603.7–629.6 ms` 降到约 `325.7 ms`，大约减少一半。P95 距离 300 ms 挑战线还差约 29 ms，但常规 P1 门槛全部通过。

10 MB 首屏阶段拆解：

| 阶段 | P50 | P95 | 说明 |
|---|---:|---:|---|
| 文件读取 | 3.730 ms | 3.752 ms | 读取完整文件 |
| UTF-8 校验 | 2.984 ms | 3.789 ms | BOM 和合法性检查 |
| 前缀 md4c | 0.682 ms | 0.877 ms | 最多 32 KB |
| 前缀布局初始化 | 0.141 ms | 0.267 ms | 首屏前缀 |
| 前缀可见布局 | 6.567 ms | 9.744 ms | 当前屏 + 上下各一屏 |
| 前缀绘制 | 1.759 ms | 4.186 ms | 当前屏块绘制 |

完整文档仍在后台继续解析，不计入首屏：

| 阶段 | P50 | P95 |
|---|---:|---:|
| 完整 md4c | 191.209 ms | 225.246 ms |
| 文档后处理 | 7.821 ms | 8.439 ms |
| 完整文档解析总计 | 207.432 ms | 238.728 ms |

前缀 md4c 和可见布局合计仍保持在毫秒级，不随 10 MB 全文同步增长。

## 3. 测量口径

### `parse`

从后台线程开始调用 `LoadFileAndParse` 计时，到完整文件读取、UTF-8 校验和完整 md4c 解析全部结束。不包含事件排入 UI 队列和完整文档替换后的绘制。

### `file_read`

读取完整文件字节。10 MB 数据通常已在 Windows 文件缓存中时约 3–4 ms。

### `utf8_convert`

BOM 检查、UTF-8 合法性校验和必要的字节整理。移除 `wxString` 往返后不再执行宽字符转换。

### `prefix_md4c_parse`

安全前缀最多 32 KB 的 md4c 解析耗时。

### `md4c_parse`

完整文档调用 `md_parse` 的纯耗时，不包括文件读取、后处理和首屏绘制。

### `normalize`

图片块拆分、flowchart 标记和块 ID 整理。无图片文档现在走无复制快速路径。

### `layout_init`

从首次创建 `ViewLayout` 开始，到所有块的预估高度槽位和总预估高度建立完成。此阶段不执行实际文字换行。

### `visible_layout`

只累计 `LayoutFor` 对当前视口及上方一屏、下方一屏中块的真实布局耗时。不包含绘制。

### `draw`

只累计当前视口内块绘制耗时。不包含背景清除、布局初始化和日志写入。

所有新增事件都在现有 `cold_start`、`hot_open` 或 `tab_switch` 完成值计算之后写入，不使用日志写入时间污染首屏值。

## 4. 初始化优化

原实现存在两次全文级遍历：

1. 每个块调用一次 `EstimateHeight`，并在其中重复查询 DPI。
2. 首次绘制后再次遍历全部槽位，累计总高度。

本轮优化：

- DPI 比例在初始化循环外只计算一次。
- 每个块预估高度加入槽位时同步累计总高度。
- 实际布局某个块后，只更新该块高度与预估值之间的差值。
- 删除 `TotalHeight()` 的第二次全文遍历。

优化前后（尚未启用前缀首屏）：

| 项目 | 优化前 | 优化后 | 变化 |
|---|---:|---:|---:|
| 150 KB 布局初始化 P50 | 0.661 ms | 0.592 ms | -10.4% |
| 10 MB 布局初始化 P50 | 45.709 ms | 43.811 ms | -4.2% |
| 150 KB 冷启动 P50 | 293.687 ms | 292.615 ms | -0.4% |
| 10 MB 冷启动 P50 | 599.375 ms | 629.589 ms | 受本轮解析和后台波动影响 |

布局初始化有直接改善，但 10 MB 总冷启动被本轮解析时间波动抵消。`layout_init` 仍必须逐块建立槽位和预估高度，因此保留线性增长；其绝对成本在当前文档上限内可控。

启用前缀显示后，首屏只初始化前缀块，10 MB 的 `layout_init` 从约
`43.8 ms` 降到 `0.141 ms`；完整文档的槽位初始化不再阻塞首屏。

150 KB 复测中仍有一个约 `961 ms` 的独立后台长尾样本，优化前后最大值为
`959.555 ms` 和 `961.413 ms`。该长尾不改变阶段中位数结论，但说明冷启动
环境仍需要多轮统计，不能只取 P50。

## 5. 前缀首屏

当文件大于 32 KB 时，后台线程先执行以下流程：

1. 完整读取和校验 UTF-8。
2. 在前 32 KB 内寻找安全顶层边界。
3. 解析前缀并把临时文档发布到 UI。
4. 同一后台线程继续解析完整文档。
5. 完整文档完成后原位替换，并恢复当前阅读位置。

安全边界规则：

- 跟踪反引号和波浪号 fenced code，不进入代码块内部切分。
- 优先使用顶层 ATX 标题起点。
- 没有标题时使用围栏代码外的空行结束位置。
- 引用块标题和缩进标题不作为顶层边界。
- 找不到至少 8 KB 的安全前缀时不启用前缀显示。

前缀解析是临时显示。完整文档替换后，表格、链接、目录、搜索和精确滚动范围均使用完整模型。

## 6. 后续判断

- 可见布局已经是固定窗口，不需要再做“只计算前三页”的改造。
- 完整解析仍在后台消耗约 200 ms，但不再阻塞首屏。
- 如果继续追求稳定 P95 小于 300 ms，应优化固定的 Windows 进程装载和窗口显示阶段，而不是继续拆分 Markdown。
- 当前不建议做多核分段 AST 合并；前缀方案已经获得主要收益，且正确性风险更低。
