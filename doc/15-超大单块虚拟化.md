# 超大单块虚拟化与解析任务回收

## 1. 结论

日期：2026-10-23

本轮完成两项稳定性与性能改造：

1. 解析完成后立即回收对应任务线程，取消的解析也发送终止事件供 UI 回收。
2. 超长文本和超大表格在模型后处理阶段拆成连续显示块，复用现有块级虚拟化。

5 次独立进程压力采样结果：

| 场景 | 文件大小 | 冷启动 P50/P95 | 首次 paint P50/P95 |
|---|---:|---:|---:|
| 5000 行单表格 | 187 KB | 247.245 / 290.208 ms | 37.042 / 43.471 ms |
| 9.5 MB 单段落 | 9.5 MB | 261.269 / 283.375 ms | 39.102 / 45.496 ms |

两场景首屏均低于普通 100–200 KB 文档 500 ms 门槛和 10 MB 挑战线。

## 2. 解析任务回收

- 正常完成的解析事件处理前，join 并删除对应的 `ParseTask`。
- 被取消的解析在后台线程退出前发送终止事件，UI 收到后同样回收任务。
- 临时前缀事件不回收任务，因为完整解析仍在同一线程继续。
- 关闭窗口时仍保留最终兜底 join，防止进程退出时存在活动任务。

运行态验证：

```text
同一实例连续打开 12 份不同文档
打开前句柄：242
打开后句柄：242
增量：0
```

改造前，预热后每新增一份文档约增加 1 个线程句柄。

## 3. 超长文本分段

- 单个 Text Block 超过 12 KiB 时拆成连续显示块。
- 优先在换行、空格或制表符处切分；没有空白时退到合法 UTF-8 字符边界。
- 片段保留原有 InlineSpan 样式、链接和源文本顺序。
- 只有第一个片段保留列表标记。
- 片段之间取消额外段前/段后间距，视觉上保持连续段落。
- 跨片段复制不插入合成换行，复制结果与原始段落文本一致。
- 搜索和选择的块内 UTF-8 偏移仍按片段分别计算。

该方案会在每 12 KiB 边界重新开始换行计算，极长段落的局部换行位置可能与单次全文换行略有差异；正文内容、选择和复制结果不变。

## 4. 超大表格分块

- 单个表格超过 64 个数据行时拆成多个 Table Block。
- 第一块包含原表头和最多 64 个数据行。
- 后续块只包含数据行，不重复表头、不重复复制内容。
- 所有块共享根据全表单元格字符数估计的列宽提示，避免分块后列宽明显跳变。
- 块间取消额外段前/段后间距，视觉上保持连续表格。
- 交替行背景使用原表行号，避免在每个分块边界重新开始。

后续块不会重新绘制表头；用户滚过首块后，行为与普通长表格滚过表头一致。
