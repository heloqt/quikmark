# 安全软件冷启动影响测试

## 1. 结论

测试日期：2026-10-23

在 AMD Ryzen 7 8845HS 本机、交流供电和 Windows“平衡”电源模式下，未观察到退出腾讯电脑管家界面进程或关闭荣耀/QAX 后台组件后，150 KB 文档冷启动获得稳定改善。

测试开始前，用户已手动关闭腾讯电脑管家的系统防护。因此 A/B 都不是“腾讯防护开启”的对照，不能根据两组差异估算腾讯电脑管家造成的启动延迟；Intel 机器测试时也开启了腾讯电脑管家，更不能把跨机器冷启动差距归因于它。

主要结果：

- 腾讯防护已手动关闭，冷启动 P50/P95：`265.616 / 284.961 ms`。
- 在此基础上再退出腾讯托盘进程、核心服务仍运行：`265.594 / 288.557 ms`，P50 基本不变。
- 荣耀/QAX 部分关闭两轮：`297.670 / 307.102 ms`、`325.878 / 334.316 ms`。
- 恢复服务后的两轮：`308.254 / 375.783 ms`、`311.379 / 335.370 ms`。

关闭荣耀/QAX 后没有稳定降低冷启动时间。第二轮关闭状态比紧邻的恢复状态更慢约 4.7%，仍处于系统后台波动范围内，但没有改善证据。

## 3. 安全组件状态

测试开始时检测到：

- 腾讯电脑管家系统防护在 A 组开始前已由用户手动关闭；后台服务仍存在。
- 荣耀电脑管家。
- 荣耀附带或调用的 QAX、MBA 组件。
- Windows Defender 处于 Passive Mode，实时防护、行为监控、IOAV 和访问扫描均已关闭。

Windows Defender 不是本次启动路径上的实时扫描来源，因此没有关闭 Defender 服务，也没有关闭其篡改保护。

管理员权限下仍无法停止：

- 腾讯 `QQPCRTP` 服务及其 `QQPCRTP.exe`、`qmbsrv.exe` 进程。
- 荣耀/QAX 的 `QAXDefender.SDK`、`QaxEngManager` 服务及其核心进程。

可以停止的荣耀 MBA 主服务、HONOR AI/推理服务以及主要荣耀后台进程已经停止，但仍不能认定为“全部安全组件完全关闭”。该限制不影响主要结论：在系统防自保护存在时，关闭这些组件不适合作为产品性能措施。

## 4. 测试方法

统一使用约 150 KB 和 10 MB 自动生成 Markdown 文档，执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\benchmark.ps1 -Samples 20 -LargeSamples 3
```

顺序：

1. A：腾讯防护已由用户手动关闭；运行基准。
2. B：在 A 基础上退出腾讯托盘和可终止用户进程；核心防护服务仍运行。
3. C：在 B 基础上停止可停止的荣耀/QAX 服务及荣耀后台进程。
4. A2/A3：恢复服务后复测。
5. C2：再次停止可停止的荣耀/QAX 组件，在紧邻 A3 的时段复测。

每轮都重新创建进程并统计 20 个冷启动样本。为降低电源差异，所有轮次均固定为交流供电和“平衡”模式。

## 6. 阶段分析

150 KB 冷启动中位阶段耗时：

| 轮次 | 进入 OnInit 前 | 构造控件 | Show | 解析与绘制 | 合计 |
|---|---:|---:|---:|---:|---:|
| A | 79.5 | 41.6 | 114.0 | 26.9 | 265.6 |
| B | 78.4 | 40.9 | 115.9 | 27.2 | 265.6 |
| C | 119.1 | 39.2 | 108.5 | 27.3 | 297.7 |
| A2 | 94.2 | 51.7 | 119.8 | 38.7 | 308.3 |
| A3 | 93.5 | 50.1 | 130.3 | 32.6 | 311.4 |
| C2 | 125.6 | 47.6 | 118.7 | 30.0 | 325.9 |

关闭荣耀/QAX 后，控件构造和窗口显示阶段有少量下降，但进入 `OnInit` 前的进程装载阶段反而变慢，最终总耗时没有改善。该现象更像 Windows 启动调度、后台负载和安全软件卸载/清理的瞬时影响，而不是可稳定利用的优化点。

## 7. 后续建议

- 不把 A/B 与 Intel 的差异解释为腾讯电脑管家造成；缺少“同一台 AMD、腾讯防护开启”的有效基线。
- 如以后确需量化腾讯电脑管家，应先在同一台机器上测得腾讯防护开启和关闭两组，并控制后台负载。
- 不为性能验收关闭或卸载安全软件。
- 如需继续解释 Intel 与 AMD 的固定基础开销差异，应取得 Intel 的 `perf-cold.csv` 阶段日志，比较 `startup_begin`、`startup_frame`、`startup_shown` 和 `cold_start`。
- 后续代码优化应优先针对可复现的窗口构造或 `Show()` 开销；本次数据不支持继续围绕荣耀/QAX 做专项优化。
- 当前 AMD 常规文档门槛仍通过；10 MB 冷启动仍是挑战目标，不参与验收失败判定。
