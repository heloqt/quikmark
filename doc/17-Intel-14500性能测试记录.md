# Intel Core i5-14500 性能测试记录

测试日期：2026-10-24

测试对象：liteMark Release static 优化版，SHA256 `AE2638E4AB1BF5D07242F77204B8A0526CA643A6ED03B4EC3BCBCB68FA3726AD`。

本文记录 Intel Core i5-14500 测试机上的当前优化版结果，包括约 150 KB 和 10 MB 文档的冷启动、运行中打开、Tab 切换、滚动、绘制以及首屏后立即滚动/搜索压力测试。旧版 AMD Ryzen 7 8845HS 记录见 [06-P1性能测试记录.md](./06-P1性能测试记录.md)，该文档仅作为历史数据保留。

## 1. 测试结论

- 约 150 KB 文档的冷启动、运行中打开、Tab 切换和滚动均满足当前 P1 门槛。
- 10 MB 文档冷启动首屏 P95 为 `180.478 ms`，达到 `<= 300 ms` 的挑战目标。
- 10 MB 文档 Tab 切换 P95 为 `20.763 ms`，低于 `50 ms` 门槛。
- 10 MB 文档独立滚动 P95 为 `8.339 ms`，低于 `16.7 ms` 门槛，最大单帧 `11.274 ms`。
- 首屏后立即连续滚动 120 帧，未出现超过 `16.7 ms` 的帧。
- 首屏后立即搜索文件末尾内容，3 次均成功跳转，搜索跳转中位数为 `282.331 ms`。

本轮完整基准的 `Pass` 为 **True**，10 MB 冷启动挑战项也通过。

| 场景 | 样本数 | P50 | P95 | 最大值 | 结论 |
|---|---:|---:|---:|---:|---|
| 约 150 KB 冷启动首屏 | 20 | 156.676 ms | 191.805 ms | 199.873 ms | 通过 |
| 约 150 KB 运行中打开首屏 | 20 | 15.438 ms | 19.875 ms | 24.605 ms | 通过 |
| 约 150 KB Tab 切换 | 40 | 4.677 ms | 6.497 ms | 6.768 ms | 通过 |
| 10 MB 冷启动首屏 | 5 | 173.757 ms | 180.478 ms | 180.478 ms | 挑战目标通过 |
| 10 MB 运行中打开首屏 | 5 | 20.228 ms | 21.123 ms | 21.123 ms | 通过 |
| 10 MB Tab 切换 | 20 | 19.801 ms | 20.763 ms | 21.186 ms | 通过 |
| 10 MB 独立滚动 | 30 | 3.218 ms | 8.339 ms | 11.274 ms | 通过 |
| 10 MB 切换阶段滚动 | 30 | 5.247 ms | 9.220 ms | 11.083 ms | 通过 |

## 3. 测试文件

- 约 150 KB 样本：158,400 字节，20 份。
- 10 MB 样本：10,813,440 字节，5 份。
- 文件包含中英文、标题、段落、强调、链接、行内代码、列表、引用、代码块和表格。
- 测试文件由脚本在 `build\perf-fixtures` 和 `build\perf-large-fixtures` 中生成，不写入源码目录。

## 4. 测量口径

- 冷启动：从启动进程开始，到目标文档首个可读视口完成应用侧绘制。
- 运行中打开（`hot_open`）：主实例已运行，第二实例通过命名管道转发文件路径；从主实例开始处理新文档到首个可读视口完成绘制。该指标不是进程热启动。
- Tab 切换：从 `Ctrl+Tab` 操作开始，到目标 Tab 的首帧完成绘制。
- 滚动：从滚轮事件进入处理开始，到对应帧完成绘制。
- 绘制：统计单次文档绘制的应用侧耗时。
- 性能事件只在设置 `LITEMARK_PERF_TRACE` 时写入 CSV，正常使用不受影响。
- 计时终点为应用侧完成绘制，不包含 Windows 桌面合成器的额外显示延迟。

## 5. 大文件首屏优化前后

优化前数据来自 2026-10-23 平衡模式的上一版 EXE，SHA256 为 `4F0459769631D2B97815F0D409526AB07D348CF6E54F15230279E72A6E969781`；优化后为本记录中的 `AE2638E4...`。

| 指标 | 优化前 P50/P95 | 优化后 P50/P95 | P95 变化 |
|---|---:|---:|---:|
| 10 MB 冷启动首屏 | 423.195 / 432.795 ms | 173.757 / 180.478 ms | 约 -58% |
| 10 MB 运行中打开 | 301.460 / 337.618 ms | 20.228 / 21.123 ms | 约 -94% |
| 10 MB Tab 切换 | 22.802 / 23.859 ms | 19.801 / 20.763 ms | 约 -13% |
| 10 MB 切换阶段滚动 | 6.294 / 11.395 ms | 5.247 / 9.220 ms | 约 -19% |
| 10 MB 绘制 | 9.386 / 23.873 ms | 5.708 / 19.374 ms | 约 -19% |

约 150 KB 冷启动在加入首屏拆分后，P50 从 `141.022 ms` 变为 `156.676 ms`，P95 从 `147.894 ms` 变为 `191.805 ms`。这是识别可安全截断位置和拆分首屏带来的固定成本，但仍明显低于 `500 ms` 门槛。

## 6. 首屏后立即滚动与搜索压力

测试使用 10 MB 文档，在首屏 `cold_start` 完成后立即施加负载，共 3 轮。

### 立即连续滚动

每轮投递 120 个零间隔滚轮消息。

| 项目 | 结果 |
|---|---:|
| 滚动帧总数 | 355 |
| 单轮 P50 | 1.705 / 1.740 / 1.748 ms |
| 单轮 P95 | 7.014 / 3.075 / 3.152 ms |
| 全局最大值 | 9.308 ms |
| 超过 16.7 ms 的帧 | 0 |
| 超过 50 ms 的帧 | 0 |
| 后台解析完成时间中位数 | 282.031 ms |
| 解析期间 UI 响应 P95 | 13.158 / 21.846 / 23.320 ms |

原始追踪显示，后台 `parse` 完成前已经处理了多个滚动帧，说明首屏渲染与后台解析可以并行工作。

### 立即搜索文件末尾

文档末尾放置唯一标记 `LITEMARK_END_MARKER_20261024`，首屏完成后立即打开查找栏并搜索。

| 项目 | 结果 |
|---|---:|
| 成功跳转 | 3 / 3 |
| 搜索跳转耗时 | 280.349–308.165 ms |
| 搜索跳转中位数 | 282.331 ms |
| 最终滚动位置 | 18,106,602 / 18,107,267（文档末尾约 99.996%） |
| 搜索期间 UI 响应 P95 | 1.393 / 6.477 / 4.803 ms |
| 搜索后绘制 P95 | 15.357 / 19.390 ms |

搜索耗时接近完整后台解析耗时，说明当前搜索需要等待全文解析/索引完成。等待期间窗口保持响应，没有冻结或消息泵超时。

## 7. 复现方式

关闭所有 liteMark 实例，准备 Release 静态版后执行完整基准：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\benchmark.ps1 -Samples 20 -LargeSamples 5
```

连续滚动压力：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\continuous-scroll-benchmark.ps1 `
  -Events 120 -IntervalMs 0
```

首屏后立即滚动/搜索使用独立专项采样脚本完成；结构化结果和原始 CSV 保存在测试包的 `results` 目录中。
